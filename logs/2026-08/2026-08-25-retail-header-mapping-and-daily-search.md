# 2026-08-25(4) 리테일 파서 위치고정→헤더명 매핑 · listing 오염 사고 · 데일리 검색창

## 무엇 / 왜
사용자가 리테일앤인사이트 상품관리 갱신을 올렸는데 **전체가 미매칭**으로 떴다. 원인 추적 →
리테일이 다운로드 양식을 **17열 → 9열**로 바꿨고(컬럼 전체가 한 칸 왼쪽으로 밀림), 위치 고정
파싱(`cols`)이 **상품명을 코드로** 읽고 있었다. 사용자 지시로 v1/v2를 모두 받는 구조로 전환.

## ★ 사고 — listing 조용한 오염
파싱이 틀린 채 **'전체 교체'가 이미 커밋됐다**(`data(listing): retail 갱신 (331건)` 07:17:10Z).
결과: `listing_retail.csv` 의 상품번호/코드 = 상품명, 상품명 = 규격, **판매가·정가 전건 0.0**.
8/12 정상본(323건)을 덮어썼다. 예외 없이 통과했기 때문에 **아무도 모르게** 저장됐다.
→ 파서 수정 후 **전체 교체 재파싱**으로만 복구된다(listing 스냅샷 박제 함정과 동일 계열).

## 한 것

### 1. 원인 확정 (실증)
- A열 바코드를 `retail_barcode_map`(556행)에 대조 → **328/331 매칭**. 데이터는 멀쩡했고
  순전히 조회 위치 문제였다(2026-08-20 자사몰 hapo 오탐과 동일 패턴).
- cmm이 읽는 col 2 = 실제 '상품명', col 17(판매가)·col 16(정가)은 **열 자체가 없음**.
- 저장 raw(`listing_retail.xlsx`)도 이미 9열 → "사용자가 다른 메뉴에서 받은 파일"이 아니라
  **리테일이 실제로 양식을 바꾼 것**. (초기 진단을 이 근거로 철회했다.)

### 2. 구현 — `cols_by_header` 축 신설 (core/workflows/channel_margin_monitor.py)
- `_resolve_cols_by_header(ws, cfg)` 신설: 헤더 라벨 → 컬럼 인덱스 해소.
  값은 str 또는 **list(앞에서부터 있는 것 채택)** — `판매가: ["기본등급 할인가", "정상가"]`.
- **필수 컬럼(상품번호·코드·상품명·판매가) 미발견 시 즉시 `ValueError`** + 실제 헤더 목록 출력.
  이번 사고처럼 조용히 오염되는 경로를 구조적으로 차단.
- **서브헤더 행 방어**: 코드 칸 값이 헤더 라벨 집합에 있으면 skip(`data_start` 만으론 불충분 —
  v1은 r2 배송유형 서브헤더, v2는 r2 공백).
- `extra_cols_by_header` 도 같은 방식(규격·입수·품절여부).
- 타 채널은 `cols`(위치 고정) 경로 그대로 — `by_header` 분기라 **회귀 없음**.
- 커밋 `ecc77d4d`.

### 3. 사용자 확정
- **정상가 = 수수료(2%) 붙기 전 가격** → 판매가 자리에 그대로 넣으면 기존 정산식(`×0.98`) 정합.
- v1/v2를 명시 분기하지 않고 **헤더명 매핑 하나로** 흡수(A안 채택). v3가 와도 라벨만 같으면 무수정.

### 4. 데일리 대시보드 검색창 (app/pages/0b_데일리대시보드.py)
당일 마진 테이블에 검색 추가. 보기 라디오 옆 `st.columns([1,2])`.
**관리코드+상품명+채널**을 한 문자열로 합쳐 매칭 · **공백=AND · 쉼표=OR** · `_nfc`+lower 정규화 ·
`str.contains(regex=False)` (특수문자 `(`·`[T]`·`*` 안전) · 히트수 캡션 · 빈 결과 메시지 분리
(기존 "✅ 이상 없음"과 혼동 방지). **상단 지표·XLSX 다운로드는 전체 기준 유지**(의도적).
커밋 `51c6e9e3`. 페이지 파일이라 **Reboot 불요**.

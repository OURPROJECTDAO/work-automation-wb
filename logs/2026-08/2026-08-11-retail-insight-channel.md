# 2026-08-11 — 채널마진모니터 리테일앤인사이트(10번째 채널) 추가

## 무엇 / 왜
사용자 요청: 리테일앤인사이트를 채널마진모니터에 추가. 입력 2종 = ① 리테일 상품 다운로드
`등록된_상품_정보_*.xlsx`(559행·32열) ② `토마토_바코드변환.xlsx`(바코드↔관리코드 601행).

**이 채널이 기존 9채널과 결정적으로 다른 점**: 다운로드 '상품코드' 자리에 **바코드(EAN-13)만** 오고
우리 관리코드가 없다. cmm이 처음 만나는 형태(지금까지는 전부 다운로드 안에 우리 코드가 있었음).

## 설계 판단
### (1) 신규 축 `code_map` — 조회 시점 변환
`parse` 시점에 관리코드로 치환하지 않고 **`compute` 시점에 변환**한다. listing에는 바코드가 그대로
저장되고, 변환표를 고치면 **상품관리 재다운로드 없이 즉시 반영**된다(매핑이 계속 늘어날 채널이라 이게 맞음).
- `cfg["code_map"]={"file":"retail_barcode_map.csv"}` → `load_references(ref_dir, code_map_file)`가
  `refs["code_map"]`으로 로드 → `compute`가 `rec["코드"]`(바코드)를 관리코드로 바꿔 resolve/baseline/floor에 사용.
- 변환표에 없으면 `비고="바코드 미매핑"`(관리코드 미등록과 구분 — 조치가 다름).

### (2) N(합포량) — 이 채널의 진짜 난점
리테일 등재 1건이 우리 박스 1개가 아니다. 예: 리테일 '코카콜라 355ml 업소용' 38,600원 ≈ 박스매입 15,931×**2**.
N=1로 두면 **173건이 마진 30%+** 로 뜬다(전부 오탐).
- 다운로드의 `입수` 컬럼으로 자동 계산하려 했으나 **신뢰 불가**: 스팸 클래식(입수40·규격 200g*20 → 2) 처럼
  맞는 행도 있고, 칠성사이다 제로(입수24·규격 355ml*24 → 1인데 실제 가격은 2박스)처럼 어긋나는 행도 있다.
- ★ **다행히 `hapo_multiplier.csv`가 바코드 키**다(스마트스토어가 n_source="download"=바코드를 N 키로 쓰기 때문)
  → **177건이 이미 채워져 있고**, 적용 시 마진 중앙값 6.6%로 정상화.
- ⚠️ 단 hapo는 **채널 무관** 가정이라 리테일에서 어긋나는 케이스 발견(티오피 200ml hapo N=3 → 리테일은 2,
  마진 −54.7% / 참맑은 175ml 7종 hapo N=3 → 전부 −3~−5%). → **변환표에 `N` 열을 두고 채널 전용 override**로
  해결. 우선순위 = 변환표 N → hapo(바코드) → 1.

### (3) 가격변경 = 알리와 동일(multi_filter)
별도 업로드 양식이 없어 **다운로드 원본이 곧 업로드 양식**(사용자 확정). 알리용 `build_multi_filter_xlsx`를
일반화해 재사용 — 기하/라벨을 `price_form` 우선(→consolidate→채널 기본)으로 읽게 하고,
**복수 가격칸**(`price_labels`)과 **숫자셀**(`price_cell:"num"`)을 지원. 리테일은 정상가·기본등급 할인가가
전건 동일(할인율 0)이라 **두 칸에 같은 권장가**를 기입한다.

- **core `channel_margin_monitor.py`** (커밋 `e66de968`)
  - `load_references(ref_dir, code_map_file=None)` → `refs["code_map"]`.
  - `compute`: 바코드→관리코드 변환 · N override(변환표 N 우선) · `비고="바코드 미매핑"`.
  - `CHANNEL_CONFIG["리테일앤인사이트"]` 신설 — key `retail` · 수수료 **2%** · `ship_fee_const 0`(배송비 수입 없음) ·
    `real_ship 2700` · `baseline_col "토마토"` · `n_source "ref"` · header_row 1 · **data_start 3**(r2=배송유형 서브헤더) ·
    cols{상품번호2, 코드2(바코드), 상품명3, 판매가17(기본등급 할인가), 정가16(정상가)} ·
    extra_cols{리테일규격4, 입수5, 품절여부15} · price_form multi_filter.
  - `build_multi_filter_xlsx` 일반화(단일시트·price_labels 복수·price_cell num·req_num을 pf에서도).
- **reference `retail_barcode_map.csv`** 신설 556행(커밋 `18fb5bd1`) — 바코드/관리코드/N/상품명.
  사용자 제공 변환표 601행에서 바코드 중복 45건 제거.
- **page `2_기준데이터관리/5_리테일앤인사이트.py`** 신설(커밋 `b25adf50`) — 검색+인라인 편집+전체 CSV 교체,
  기존 기준데이터관리 패턴(st.form 경합 방지·sanitize_ref_df) 그대로. N 설명·현황 메트릭 3종.
- 페이지 6은 **무수정** — 채널 selectbox가 CHANNEL_CONFIG 키에서 자동 생성되고 multi_filter 분기는 이미 있음.

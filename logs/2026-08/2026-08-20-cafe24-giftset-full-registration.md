# 2026-08-20 자사몰(카페24) 추석26 선물세트 전 라인업 등록 + 무료배송 리스팅 신설

## 무엇 / 왜

추석26 선물세트 시즌 라인업(ERP 특별단가 전표 40행)을 **자사몰에 전건 등재**하고,
개별발송 유도용 **1세트 무료배송 리스팅**을 짝으로 만들었다. 자사몰 상품 등록은 이번이 첫 작업이라
과거 업로드본(36행 CSV)에서 양식을 역해독하는 데서 시작했다.

## 한 것

### 1. 업로드 양식 역해독 (신규 워크플로우 `cafe24-register`)
- 업로드 90열 / 다운로드 88열 = **다른 양식**. 실제로 채우는 건 13~15열뿐.
- **공급사 = 배송조건 그룹**. `일반합포{박스내품}` — HC/HD/HE/HJ/HK/HL = 2/3/4/5/6/8, HM = 무료배송.
  등재 36건 중 35건이 `unit_list.박스내품`과 정확히 일치해 규칙 확정 → **자동 배정 가능**.
- 최대 주문수량 = 박스내품 × 10 (34/39 예외 없음).
- 공급가 500000 = 안 쓰는 고정 더미(등재 전건이 지금도 500000, 판매가만 실가).
- 상세설명은 **HTML `<img>` 필수** — URL만 넣으면 텍스트로 박힌다(사용자가 스크린샷으로 지적).
- 대표이미지(A1)는 **CSV로 못 넣음**(카페24 내부 해시 경로) → zip 전달 후 수동 등록.

### 2. 무료배송 가격 규칙
`무료배송가 = 1세트가 + 3,000`, **마진 불변**. PG 3.3%가 판매가·배송비에 동일 적용되므로
`2,901 ÷ 0.967 = 3,000`으로 정확히 떨어진다. 기존 `P0000BCI`(G호 3세트 89,400 = 28,800×3+3,000)가 이미 이 규칙.

### 3. cmm 무료배송 대응 (`bf88a36`)
자사몰 `ship_fee_const:3000`이 전 리스팅에 적용돼 무료배송분 마진이 부풀던 문제.
```
"ship_fee_zero_if": {"col_name": "공급사", "values": ["S00000HM"], "col_fallback": 50}
```
`_parse_csv_download`에 `_ship(row)` 분기 추가. **헤더명 우선 + 위치 폴백**(공급사 50열은 A~T 고정구간 밖).
- 골든 730행: 배송비 3000→0 **정확히 3건**(BCK·BCJ·BCI), 나머지 727건·배송비 외 전 필드 동일.
- 컬럼 1칸 밀린 CSV로도 3건 정상 판정(헤더명 조회 내성 확인).
- 효과: `P0000BCK` 표시마진 16.12% → **실제 5.64%**, `P0000BCI` 14.72% → 11.86%.

### 5. hapo N 등록 (`dc4b957`)
`hapo_multiplier.csv` **3,358 → 3,408행 (+50)**. N = 세트수 ÷ 박스내품.
분포: 0.3333×17 · 0.25×15 · 0.2×14 · 0.1666×4.
**세 export를 합쳐** 판매중지분(14건)까지 포함 — 판매Y 필터본만 봤으면 재개 시 또 역마진으로 떴을 것.
제외 2건 = `P0000BCI`(세트3=박스내품3 → N=1) · `P0000BCJ`(모델명 공란).

## 검증

- cmm 골든 730행 신·구 diff → 의도한 3건만 변경, 나머지 전 필드 동일

## ★ 내 오류 (정직 기록)

이번 세션 **오판 3건**. 전부 사용자가 지적해서 발각됐다.

1. **`hapo_multiplier` 컬럼 인덱스 오독** — 헤더명 대신 위치로 읽어 합포량 자리에 채널을 가져옴.
   전건 N=1 폴백 → "자사몰 선물세트 33건 전건 마진 −113~−420%"라고 보고. 실제 데이터는 멀쩡했다.
   **이 함정은 KB에 이미 등재돼 있었는데 내가 그대로 밟았다.**
2. **700건 export를 전체 카탈로그로 착각** — 진열 Y 필터본이었다. 이미 등록된 5건을 "미등록"으로
   판정해 신규 등록 CSV에 넣었다. "listing에 있는데 export엔 없는 게 7건"을 **직접 계산해놓고도**
   "삭제됐나 보다"로 흘려보낸 게 결정적. 사용자의 "723건 아니었어?" 한마디로 발각.
3. **`45-20-+01`을 오타로 단정** — 시트만 보고 "자사몰 오타"라고 했으나 ERP 관리코드 자체가 그렇다.
4. (부수) 8/4 로그의 미해결 항목(`P0000BCK` −283%)을 **이미 해소된 줄 모르고** 미해결로 들고 왔다.

공통 원인 = **한 소스만 보고 결론을 확장.** 2026-08-13에도 같은 유형 3회를 기록했는데 재발했다.
처방: (a) 참조 CSV는 **항상 헤더명으로** 접근 (b) 외부 export는 **총 건수부터 사용자 확인**
(c) 내 손으로 계산한 불일치 수치를 **설명 없이 넘기지 않는다**.

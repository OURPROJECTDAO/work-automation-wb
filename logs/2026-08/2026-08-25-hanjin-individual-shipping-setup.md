# 2026-08-25(3) 한진택배 개별발송 워크플로우 신설 — 양식 역해독·1차 실행·회수 검증

## 무엇 / 왜
추석 시즌에 채널 밖 개별 발송(B2B·지인·단체)이 늘어 상시 업무가 됨. 사용자가 한진 접수 양식 샘플을
제공 → 규칙 도출 → 실주문 2건 end-to-end 수행 → 회수 파일 검증까지 한 사이클 완주.

## 한 것

### 1. 양식 역해독 (21열)
`Sheet1`·헤더 1행·데이터 2행부터·병합/수식/유효성검사 없음(자동필터만).
샘플이 실제로 채운 건 9칸(C/D/G 보내는분 · H/I/L 받는분 · O/P 품목).
우편번호(F·K)를 비워도 접수되는 구조로 보였으나, 검증 단계에서 채우는 쪽으로 확정.

### 2. ★ 행 분할 규칙 확정
**1행 = 송장 1장.** `P 박스수량`을 키워도 한진이 송장 1장으로 묶으므로 행 복제가 유일한 방법.
- 사용자 확정: **기준은 세트**, `(box/N)`의 N = **한 송장 최대 세트수 = `product_master.박스내품`**.
- `행수 = ceil(세트수 ÷ 박스내품)` · `행별 세트수 = min(박스내품, 잔여)` · `P = 1` 고정.
- ★ 내 중간 오판: 처음엔 "박스 1개 = 송장 1장"으로 가정했고, 다음엔 `product_attributes.합포수량`을
  근거로 잡았다. **선물세트는 합포수량이 전건 1이라 결과가 우연히 같아서** 둘 다 맞는 것처럼 보였다.
  일반 상품(합포수량 2)이 섞였으면 틀렸을 것. 사용자 정정으로 박스내품 기준 확정.

### 3. 고정값 확보
C `(주)태동유통판매` · D `010-6291-9345` · G `경기도 성남시 분당구 탄천상로 163번길 20, 1층 판교대리점`
· F 우편번호 `12963`. 사용자가 따로 말하지 않는 한 자동 적용.

### 4. 주소 검증 = 필수 단계로 승격 (사용자 지시)
2건 전수 조회. 노원 마들로 111 = 미륭·미성·삼호3차 3,930세대·32동(01909),
의정부 신곡로 36 = 한일·삼익아파트(11731, 상세건물명 101~106동 → 101동 1206호 유효).
배달 메모 "19동옆 미륭기관실"도 단지 구성(17~23동 미륭)과 정합 확인.

### 5. 1차 실행 — 23행
- 노원(01909): 풍성한S호 39(3×13) + 애경마음14호 34(6×5+4) = 19행
- 의정부(11731): 풍성한S호 2 + 애경마음14호 2 + 동원참치18호 6(3×2) = 4행
- 배달장소 메모는 S 배송메세지1에 전 행 반복 기입.

### 6. 회수 검증 + 정제본
한진 "재출력 세부내역"(시트 `상세내역`·**2단 헤더**·데이터 3행부터·48열) 수령.
- **수량 대조**: 39/34/2/2/6 전건 일치, 주문 외 항목 0, 운송장번호 중복 0, `AC 수량` 전건 1.
- **분할 검증**: `(box/N)`이 박스내품과 전건 일치, 행수 = ceil 값과 일치, N 초과 행 0.
- 정제본 = D·M·N·T·Z·AK 6열만 남긴 배포용 워크북(헤더고정·필터·운송장번호 텍스트 서식).

## 검증
- 접수 양식: 21열·헤더 무변경·필수칸 공란 0·세트 합계 재검산 일치·우편번호 앞자리 0 보존(`01909`).
- 회수 파일: 위 2종 검증 전건 통과. 우리가 쓴 품목명 문법이 `AK`·`AP`로 그대로 회신됨 →
  **양식·분할 규칙이 한진 쪽에서 수용됨을 실증**.

## ★ 내 오류 (정직 기록)
1. **추정 우편번호를 기입**했다. 보내는분 주소의 우편번호를 인접 번지(탄천상로163번길 10 = 13636)에서
   추정해 넣었는데, 한진 회수본이 **12963**으로 잡았다. 추정치를 "추정"이라 밝히긴 했으나
   **애초에 넣지 말았어야 했다**. → 정본 12963 확보, 워크플로우에 금지 규칙 등재.
2. **검증 전에 결론을 냈다.** 주소 점검 요청을 받자마자 "실제로 하나 걸립니다"라고 단언했는데,
   마들로가 상계·중계 도로라는 인상만으로 월계동 아파트와 불일치할 거라 지레짐작한 것이었다.
   조회해보니 정상이었다. **KB에 이미 등재된 "신호 하나를 확인 없이 결론으로 확장" 패턴 재발.**
3. 사용자가 "저건 샘플이니 무시해"라고 한 범위를 **보내는분 주소까지로 넓게 해석**해 비워뒀는데,
   실제로는 이름(홍길동)만 더미였고 주소는 실제였다. 지시 범위를 임의로 확장하지 말 것.

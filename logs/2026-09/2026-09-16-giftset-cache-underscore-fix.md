`14_선물세트시즌.py` `_sales(months, _index)` — 파티션 sha 를 캐시 키로 넣으려고 만든 인자를
**`_` 로 시작하는 이름**으로 선언했다. `st.cache_data` 는 **밑줄로 시작하는 인자를 해시에서 제외**한다.
→ 캐시 키가 사실상 `months` 하나 → 재적재해도 `('2026-07','2026-08','2026-09')` 그대로 → **600초 동안 옛 파케이**.

## 변경 (page-only · 커밋 app `c7df2593`)
1. `_sales(months, part_index)` — 인자명 밑줄 제거 → sha 가 실제로 캐시 키에 들어감.
2. `_read_blob()` 신설 — 파티션을 **`git/blobs/{sha}`(내용 주소)** 로 읽는다. 경로 기반 contents raw 는
   방금 PUT 한 파일을 옛 바이트로 줄 수 있고(pitfalls 2026-07-20), 그러면 옛 내용이 새 sha 키로 600초 캐시된다.
   sha 없거나 실패 시에만 `store.read_partition` 폴백.
3. `_today_kst()` — 기준일 기본값·파일명·상태 갱신일을 KST 로. Cloud 서버는 UTC 라
   `pd.Timestamp.now()` 가 **KST 09시 전엔 어제** → 기준일=어제 → 시즌창(end=기준일)이 오늘분을 잘라냄.
4. 적재 최신일 표시 — `sales_YYYY-MM` sha 앞 8자리 병기. 1일 차이는 `st.info`("오늘 매출 아직 없음"),
   2일 이상 `st.warning`. (종전엔 1일 차이를 캡션으로만 보여 stale 이 정상처럼 보였다.)

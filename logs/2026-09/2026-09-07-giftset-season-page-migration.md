# 2026-09-07 선물세트 시즌 관제판 — 구 VBA `선물세트` 시트 앱 이관

## 무엇 / 왜
`스마트스토어_마진율_계산기_V12.xlsm` 의 **`선물세트` 시트**(sheet17)를 Streamlit으로 이관.
시즌 한정 트랙이라 그동안 앱 미개발이었으나(giftset-season-ops 성격 절), 사용자 요청으로 착수.

## 구 시트 해부 (34행 r3~r36 × A~Z)
B 관리코드 하드코딩 · C~G `재고 기입` VLOOKUP/XLOOKUP · H 재고금액 · **J~T 채널별 매출 11개
SUMIFS(영업이익현황 P열=판매금액, B=상호명, D=관리코드)** · I 나들외 · U 기타(실장님) · V 전체 ·
W 일평균(7일) · X 당일 · Y 당일박스 · Z 재고−당일.

### 죽어 있던 것 (원문 그대로 옮기면 안 되는 이유)
1. **N열(11번가) SUMIFS 3번째 인자가 행마다 엉뚱한 셀** — r3=`B16`·r4=`B19`·r6=`B5`… 드래그 사고,
   **`#REF!` 2건**(r11·r19). 값이 전부 0이라 티가 안 났다.
2. **D열(유통기한 및 재고)** = `XLOOKUP(B, 선물세트목록!Z:Z, 선물세트목록!AB:AB, "품절")` 인데
   **AB는 빈 열**(실제 데이터는 AC 규격·AD 재고) → 전건 0. 사용자 결정 = **버림**.
3. H·I·U가 행마다 수식/값 뒤섞임(대부분 값으로 굳어 재계산 안 됨).
4. **W~Z 단위 붕괴** — 이름은 '판매량/판매박스'인데 SUMIFS가 잡는 건 **판매금액**.
   `Y = X/F`(당일매출 ÷ 박스매입가)는 박스수가 아니고, `Z = H − X×0.8`은 금액−금액×0.8 혼용.
5. 45-12-06 r10·r11 **중복**.
6. 라인업 34행 고정 → 구 코드 5종 잔존(`45-20-+01`·`45-12-04`·`01-19-04`·`01-19-06`·`16-31-02`),
   현행 라인업 **13종 누락**(J호·L-2·L-3·레드라벨·복합100호·마음14호·정관장·스페셜10호 등 신규 전부).
7. 채널 낡음 — 멸치·11번가는 사장 채널, **자사몰(카페24) 없음**.
8. 이익·마진 축 자체가 없음(전부 매출액).

## 설계 (사용자 확정)
- **성격 = 셋 다**(조회 관제판 + 가격변경 시트 생성 + 재고 경보).
- **행 = 자동 산출** — `선물세트 유니버스 ∩ (박스재고>0 ∪ 시즌매출>0)`.
  유니버스 = `product_attributes.최종분류=='선물세트'` **∪** `reference/giftset_lineup_2026.csv`.
  ★한쪽에만 있는 코드에 `결손` 플래그 → **기준데이터 구멍 탐지기 겸용**
  (2026-08-27에 3종이 attributes에 행 자체가 없어 등재갭 분석에서 통째로 빠진 전례).
- **축 4종 전부**: 채널별 매출 / 채널별 이익·마진 / 수량(세트) 소진예측 / 작년 YoY.
- **최신 매출 = 업로드하면 파케이에 자동 적재**(store.ingest).
- **노출 = 상시**, 비시즌엔 안내문만(D > 시즌창 또는 D < −15면 stop).

## 개발 중 잡은 자기 버그 2건 (기록)
1. KPI·채널군 집계를 **선물세트가 아니라 전 상품**(`cur_all`)으로 돌려 오픈마켓 10.09억·진도 67%가
   나왔다. 유니버스 산출용 프레임을 그대로 집계에 재사용한 실수 — 챗 진도판과 대조하지 않았으면
   그대로 나갈 뻔했다. **신규 집계는 반드시 기존 산출값과 원단위 대조**할 것.
2. `store.ingest`를 확인 전에 "하루치만 올리면 그 달 나머지가 사라진다"고 캡션에 적었으나,
   실제로는 `date_range_replace`라 **부분 업로드가 안전**하다. 코드를 읽고 정정.

# 2026-09-07 선물세트 시즌 관제판 — 타 페이지 재적재가 안 잡히던 캐시 stale 픽스

## 무엇 / 발단
사용자: "데이터 현황에 9월 영업이익현황을 적재했는데 선물세트 시즌 탭은 안 먹네?"
→ 적재 경로 문제가 아니라 **페이지 캐시 stale**. 두 페이지 모두 같은
`work-automation-data:master/sales_YYYY-MM.parquet` 을 쓰므로 적재는 한 번이면 된다.

## 원인
`14_선물세트시즌.py` `_sales(months)` 를 `@st.cache_data(ttl=600)` 로 걸면서
**캐시 키를 월 목록 튜플로만** 잡았다. `sales_2026-09.parquet` 은 9/1 세션에 이미 생성돼 있었으므로
데이터현황에서 **내용만 갱신**해도 `('2026-07','2026-08','2026-09')` 은 그대로 → 캐시 히트 →
TTL 600초가 만료될 때까지 옛 파케이를 그대로 내준다. **에러도 경고도 없이 조용히 옛 숫자.**

## 변경 (`app/pages/14_선물세트시즌.py` · 커밋 5e94d38a)
1. **`_part_index()` 신설**(ttl=60) — `master/` 디렉토리 목록(JSON)에서 `{YYYY-MM: blob sha}` 수집.
   디렉토리 리스팅 1회라 비용이 없다.
2. `_sales(months, _index)` — **파티션 sha를 캐시 키에 포함**. 내용이 바뀌면 sha가 바뀌므로
   같은 월이라도 캐시가 자동 무효화된다. `_load_sales(a, b)` 래퍼로 호출부 단순화.
3. **적재 최신 거래일 캡션** — 기준일 대비 2일 이상 벌어지면 `st.warning` 으로 승격하고
   적재/새로고침 경로를 안내. stale 이 **화면에서 보이게** 만든 것이 핵심(조용한 오독 차단).
4. 적재 탭: `ingest` 성공 → `cache_data.clear()` → `st.rerun()` 으로 즉시 재계산.
5. 사이드바 새로고침 버튼에 "다른 페이지에서 적재했는데 반영이 안 되면" 안내 추가.

## 검증
`ast.parse` 통과. 캐시 키 = `(months, ((월, sha), …))` 로 내용 변경 시 반드시 미스.
sha 조회 실패 시 빈 dict → 키가 `(월, "")` 로 고정되나 ttl 600 은 그대로 동작(하위호환).

## ★ 같은 계열 잠복 (전역 함정 등재)
파일 **목록·개수·기간**만 캐시 키로 쓰는 로더는 전부 같은 병을 앓는다. 확인된 것:
- `app/pages/9_재고지능.py` `_sales_recent(months: int)` — 키가 정수 하나.
- `app/pages/0b_데일리대시보드.py` `_recent_month_sales(n: int)` — 키가 정수 하나.
둘 다 "최근 N개월"이라 재적재해도 키가 안 바뀐다. 지금 당장 오작동 보고는 없으나
(TTL 이 짧거나 재적재 직후 열 일이 드묾) **동일 처방(sha/etag 키) 대상**으로 남긴다. 미수정.

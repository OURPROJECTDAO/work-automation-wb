# 2026-09-03 자사몰(카페24) 천년경영 업로드 — ★신규 채널 + 배송비 이중계상 발견

## 무엇 / 왜
사용자 요청 "자사몰 천년경영 입력하는 시트 만들어줘, 한번에 엑셀로".
입력 = ERP `판매처상품매출통계`(11행) + 이지어드민 `확장주문검색`(28행 + 합계행 1).

## ★ 자사몰은 앱 파이프라인에 없다
`cheonnyeon_upload.GROUP_TO_SHEET`에 **`태동마트자사몰` 키가 없다** → `target is None → continue`로 **조용히 버려진다**(에러 없음).
그래서 같은 규칙을 오프라인 재현해 산출. 11코드 전건 박스코드(`sub_list` 미등록)라 낱개 이동 없이 전체 시트 하나.

## ★★ 최대 발견 — 매출통계 `선결제택배비`가 2배 부풀어 있다
- 매출통계 행합 **138,000원** vs 실제 **72,000원**.
- 원인: **주문 단위 배송비가 상품 라인마다 반복 기재**된다. 주문 `20260818-0000021`은 배송비 18,000원 1건인데 상품 3종의 첫 행에 각각 18,000이 찍혀 행합 54,000. 반대로 같은 상품 분할출고 행은 0으로 온다 → **규칙이 일정하지 않아 매출통계만으론 못 거른다**.
- 검증된 실제 규칙: **`배송비 = 3,000원 × 송장 건수`**. 13개 주문 전건에서 `distinct 송장수 × 3,000 = 주문 배송비` **정확히 일치**(24송장 → 72,000원).
- 배분: 송장 단위 3,000원을 그 송장에 실린 상품에 **수량 비례** 배분. 송장 1장은 발주일 1개에만 속하는 것도 확인.
- → 매출통계 값을 그대로 쓰면 배송비 66,000원 과대 → 실제기입단가 통째로 과대계상.

## 산출식
`H(실제기입단가) = (F 정산금액 + G 배송비 × 0.967) / D 수량`
- `F 정산금액`은 이미 PG 수수료 차감 후(net) → 계수 없음(스마트스토어와 동형).
- 배송비에 자사몰 PG 3.3% 반영 → 0.967.
- ⚠️ PG 수수료율이 주문마다 다름(판매가 대비 3.13~3.44%, 결제수단 차이 추정). 정산금액이 실수취액이라 상품 단가엔 무영향이나 **배송비에 3.3%를 물릴지는 확정 근거 없음**(안 물리면 총 2,376원 차이). 자사몰 정산서로 확인 필요.

## 일자 = 발주일
초기 산출은 A=실행일 일괄이었으나 사용자 지시로 **발주일 기준**으로 전환.
매출통계는 상품 단위 집계라 발주일이 없음 → **확장주문검색을 기준 소스로 교체**하고 `(발주일 × 관리코드)`로 재집계.
확장주문검색이 매출통계를 완전 재현하는 것 선확인(11코드 수량·정산금액·평균단가 전건 일치). 상품명(어드민 옵션)만 매출통계에서 가져옴.

**11행 → 18행**(발주일 8/4~8/28 11일자). 같은 상품이 여러 날 팔린 건 날짜별로 갈림(31-03-05 4줄·35-16-01 2줄).

| 항목 | 값 |
|---|---|
| 행수 | 18 |
| 수량 | 48 |
| 정산금액 | 1,340,536 |

산출 `자사몰_천년경영업로드_20260804-0828.xlsx` 2시트(자사몰전체 + 배송비_근거 24송장).
H는 라이브 수식(`=(F+G*0.967)/D`), 관리코드 전 행 텍스트 서식(`24-05` 날짜변환 방지).

# 발주서출력업무 — 합포 셀나누기 버그픽스 (코드끼리 붙은 케이스)

## 무엇
사용자 발주서(발주최종.xls) 54·55행 카프리썬 합포(24-49-04 사과맛 + 24-49-01 오렌지망고)가
분리 안 되고 한 행(erp `24-49-0424-49-01`·수량4)으로 뭉쳐 나오는 버그 수정.

## 왜 (근본원인)
- ERP 매출통계 HTML은 다른상품 합포를 **셀 안 중첩테이블(tableGridA)의 여러 `<tr>`**로 표현
  (코드/상품명이 행 분리). `pd.read_html`이 이 중첩행을 그냥 이어붙여 뭉갬.
- 기존 split_multiproduct_cells 감지 2종이 이 케이스에 둘 다 실패:
  ① 어드민옵션 [대괄호코드] → 카프리썬 상품명엔 대괄호 없음
  ② 옵션추가항목1 숫자코드 → 이 행은 옵션1이 비어있음(NaN)
  → 코드끼리 붙은 신호(`24-49-04`+`24-49-01`)가 erp관리코드 필드에만 있어 미감지.
- 대조: 같은 파일의 코카콜라제로+환타 합포(31-22-02/31-47)는 상품명에 대괄호 있어 기존 로직으로 정상 분리됨.

## 변경 (core/workflows/logistics_order.py, 커밋 bda98ee2f9)
- **parse_sales_report를 lxml 기반으로 교체**(+read_html 폴백). 중첩테이블 행 경계를
  `_SENTINEL="\x1f"`로 보존(뭉개지 않음). 빈 셀은 None(NaN)으로 내보내 fill_management_code 호환.
  - 본 데이터 테이블 = tableGridA 아닌 테이블 중 'erp관리코드' 포함·행 최다. 헤더행 위 노이즈(품절 사전경고) 스킵 동일.
- **split_multiproduct_cells에 sentinel 1순위 추가**. sentinel 있으면 그 경계로 N분할,
  코드 = erp행값 → (없으면) 옵션1행값 → (없으면) 상품명 [대괄호코드] 순으로 도출.
  대괄호(2순위)·옵션1 숫자코드(3순위)는 폴백으로 유지. 총수량·정산 ÷N(기존 균등분배 동일).

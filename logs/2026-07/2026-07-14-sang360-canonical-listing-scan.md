# 상품360 채널 등재 스캔을 canonical_code로 확장 (낱개/소분 등재 포함)

## 무엇
- 상품360 카드(11_상품360.py)의 "채널별 등재 현황"이 **박스 관리코드로 올라간 리스팅만** 잡던 것을,
  **낱개(PC+상품코드)·소분 코드로 올라간 리스팅까지** 함께 잡도록 확장.
- 표에 **등재유형**(박스/낱개/소분/합포)·**등재코드**(실제 등록된 판매자상품코드) 두 컬럼 추가.

## 왜
- 기존 매칭이 `_nfc(r["코드"]) == code`(박스코드 정확일치)라, 같은 상품이라도 채널에 **낱개(PC코드)로
  등록된 리스팅은 코드가 달라 전혀 표시되지 않았음**. 예: 델몬트칵테일후르츠(17-02)는 쿠팡에 12개
  낱개옵션(PC002764·1~12개)이 올라가 있는데 상품360엔 "쿠팡 미등재(⚪)"로 잘못 보였음.
- 사용자 요청: 관리코드로 검색하면 낱개코드로 올라간 상품번호도 보이게.

## 변경 (page-only, app repo)
- app/pages/11_상품360.py (커밋 ec29bf70):
  - 등재 스캔: `sub = [r for r in recs if cmm.canonical_code(r["코드"], refs) == code]`
    (기존 박스 정확일치 → canonical_code로 박스/낱개(PC)/소분 통일 매칭).
    canonical_code는 이미 cmm에 있는 순수함수(PC낱개→상품코드행 관리코드·소분→원코드·박스=자기자신) → core 무변경.
  - listing_rows에 `등재유형`(=compute의 코드유형)·`등재코드`(=rec["코드"]) 추가 + column_config.
  - 안내 문구/미등재 info를 "박스·낱개·소분 전부 확인" 반영.
- compute()가 이미 코드유형·매입가·마진율을 코드유형별(낱개=낱개매입단가)로 정확히 산출하므로
  마진/필요판매가 계산은 자동으로 올바름(별도 수정 불요).

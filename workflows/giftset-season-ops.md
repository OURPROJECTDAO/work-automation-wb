# workflows/giftset-season-ops.md — 선물세트 시즌 운영 (추석/설)

> **성격**: 챗 네이티브 · 앱 미탑재 · **시즌 한정 트랙**(명절 D-31 개시 ~ D+15 정산 후 닫음).
> 선물세트는 두뇌④ 시즌 제외 축(⑧)이라 채널마진모니터·두뇌④ 자동 감시가 **안 붙는다**.
> 그래서 시즌 동안만 사람+AI 캐치업으로 대체 감시하는 트랙. 시즌 끝나면 같이 닫는다.
> 정본 스코프 = **오픈마켓(나들·오프라인 제외)**. 나들/오프라인은 이 트랙 밖(별도 관리).

## 0. 한눈에 로직

```
[준비 D-31까지]  등재갭 해소 + 분류 등록 + 매입 인상 전가 + 기준선 박제
        ↓
[관측 D-30~20]  주2회 — 진도 밴드 대비 초기 반응만 확인 (이 구간 매출 15%)
        ↓
[승부 D-19~10]  매일 — 인하 재원 집행. 여기서 88% 결정
        ↓
[마감 D-9~3]   격일 — 인하 vs 이월 판단 (손익분기 3%p)
        ↓
[정산 D+1~15]  2회 — 실적 확정 · 이월 재고 · KB 기록 · 트랙 닫기
```

## 1. 목표 체계 — 마진을 "예산"으로 전환

볼륨 우선(회사 방침) 상황에서 마진을 *지키는 것*으로 두면 목표 미달을 감수하게 되고,
반대로 무제한 인하하면 바닥을 뚫는다. → **인하 재원(budget)** 개념으로 전환한다.

| 항목 | 2026 추석 값 | 성격 |
|---|---|---|
| 매출 목표 | **15.0억** | 커밋(양보 불가) |
| 이익 하한 | **1.10억** | 추석25 0.91억 +21% |
| 마진 하한(포트폴리오) | **7.3%** | = 이익하한 ÷ 매출목표 |
| 계획 마진 | **8.8%** | 채널별 목표 가중 |
| **인하 재원** | **2,200만원** | = 매출목표 × (계획마진 − 마진하한) |
| 개별 상품 절대하한 | **3.0%** | 두뇌④ `MIN_SELL_MARGIN`과 동일. 예외 없음 |

- 가격 인하 = **재원의 집행**. 매 세션 **잔액**을 추적한다. "얼마 깎았나"가 아니라 "얼마 남겼나".
- **재원 소진율 > 진도율**이면 경고. (예: D-15에 진도 43%인데 재원 60% 소진 → 그 페이스면 하한 관통)
- 인상으로 회수한 마진은 재원에 **적립**한다(순액 관리).

### ★ ESM 목표의 실제 기저 = **지마켓 단독** (2026-08-12 확정)

**옥션 거래 종료**(사용자 확정). 실적상 이미 반영돼 있었다 — EasyAdmin 주문 기준 ESM 내 옥션 비중:
추석24 **54.2%** → 추석25 **28.9%** → 설26 **0.5%**. 옥션 판매중지일이 2025-11-14(추석25 종료 직후)에
몰려 있는 것과 일치. cmm ESM 파싱이 `include_row_if_col_value F=='지마켓'`인 것은 원래 다운로드
중복제거 목적이었으나, **이제 거래 정책과 일치**한다(의미가 달라짐 — 지마켓만이 곧 우리 판로).

→ 추석25 ESM 5.37억 중 **지마켓 단독은 약 3.82억**(71.1%).
→ **ESM 목표 6.0억 = 지마켓 단독 +57%.** (앞서 "+12%"로 본 것은 옥션 포함 기저와 비교한 오류)

**사용자 결정(2026-08-12) = ③ 현행 유지**(ESM 6.0억 유지, 총액 15억 유지).
대안이던 ①(ESM 4.6억으로 낮추고 차액을 쿠팡·스스 재배분)·②(총액도 13.6억으로 하향)는 기각.

**달성 경로 = 가격이 아니라 품목 수.** ESM은 폭으로 푸는 채널이 됐다.

| 지마켓 판매코드 | 코드당 필요 | 작년 대비 깊이 |
|---|---|---|
| 29개(작년 수준) | 2,100만 | +57% |
| 35개 | 1,700만 | +30% |
| **41개(전 라인업)** | **1,500만** | **+11%** |

29개로 버티면 +57%를 가격으로 만들어야 해 마진 9.0% 목표와 양립 불가.

**리스크 완화**: 옥션 단독 판매코드는 **2개뿐**(나머지는 지마켓에도 등재돼 있던 것)이라 상품이 통째로
사라지는 구조가 아니다. 설26에 옥션이 0.5%로 빠졌는데도 지마켓 단독은 설25 대비 크게 성장했다.

**체크포인트(하향 트리거)**

  (D-10 넘어가면 재배분할 시간이 없다)

⚠️ 미확인 = 옥션 종료가 **선물세트만인지 전 품목인지**. 전 품목이면 cmm ESM 기준마진·가격변경 로직과

## 6. 판단 규칙 (4분면) — 두뇌④ 4분면과 동형

| | **재고 과잉**(소진예측 > 잔여일) | **재고 부족**(소진예측 < 잔여일) |
|---|---|---|
| **진도 미달** | 🔴 **인하 집행** — 재원 차감 | 🟡 **추가 매입 검토** — CJ/동원 시즌 생산 여부 확인 |
| **진도 초과** | 🟢 유지 | 🔵 **인상 검토** — 재원 적립 |

**인하 집행**
- 1회 **−2~3%p**, **최소 3일 관측** 후 재판단. (잔여 5일 이하면 관측 없이 즉시)
- 단위 = **채널 × 상품**. 같은 세트도 ESM 미달 / 스스 정상일 수 있다.
- 3%p 절대하한 클램프 — 권장 < 3%면 3%까지만 내리고 그 밑은 막는다.
- 캐시노트·알리 제외.

**인상**
- 품절 임박(소진예측 < 잔여일)인데 진도 초과면 **올린다**. 어차피 팔릴 물건을 싸게 주는 건 재원 낭비.
- 회수분은 재원에 적립 → 다른 상품 인하 여력이 된다.

## 7. 마감 국면 전용 — 인하 vs 이월 손익분기

선물세트 잔여 재고는 **죽는 게 아니라 다음 설로 이월**된다.
★ 근거: 구성 변경은 **추석 직전에만** 발생(2024추석 구성→설25 유지 / 2025추석 구성→설26 유지).
   즉 추석 물량의 다음 설 이월은 이 상품군의 **정상 운영**. (logs/2026-07-29-giftset-season-analysis)

- **이월 비용 ≈ 3.3%** = 자금비용(연 5% × 8개월 ≈ 3.3%) + 재고 위험
- → **3%p 넘게 깎아서 지금 터는 것은 이월보다 손해**

| 상황 | 판단 |
|---|---|
| 인하폭 3%p 이내로 소진 가능 | **인하** |
| 3%p 초과 필요 | **이월** |
| 이미 이월 재고 누적 큰 품목(45-21 스팸8호·50-32 리챔G9) | 누적 부담 고려해 **인하 쪽으로 기울임** |

## 8-B. ★ 선물세트 등록 예외 규칙 (일반 상품과 다름 — 2026-08-13 확립)

### (2) 천년경영 ERP 업로드 — **항상 낱개 시트, 수량·단가 그대로 통과**
`sub_list` 멤버십이 전체↔낱개 분기의 유일 근거인데 선물세트는 전건 등록돼 있으므로 **낱개 시트로 이동**.
거기서 `J(기입수량)=D×낱개개수=D×1=D`, `K(낱개단가)=H×D/J=H` → **수량도 단가도 무변환 통과**.
즉 **1세트 단위로 팔고 1세트 단위로 ERP에 꽂힌다.**
`unit_list` 입력값(1/박스내품)은 박스 발주를 세트로 환산할 때 쓰는 값으로 ERP 업로드 경로와 별개.

### (3) 채널 등록 — 1세트 + 박스 **동시 등록**, 판매자상품코드는 둘 다 관리코드
| | 일반 상품 | **선물세트** |
|---|---|---|
| 판매자상품코드 | 박스=관리코드 / 낱개=PC코드 | **둘 다 관리코드**(PC 없음) |
| 등록 단위 | 박스 or 낱개 택1 | **1세트 + {박스내품}세트 동시** |
| 상품명 끝 | `{박스내품}개` | **`1세트` / `{박스내품}세트`** |
| 합포 N(배송) | 합포장 × 박스내품 | **합포수량 1**(attributes 전건 1) |
| 판매가 기준 매입가 | 박스=박스매입단가 | **1세트=매입단가 · 박스=박스매입단가** |

### (4) ★★ 합포 N — **채널마다 저장 위치가 다르다** (정본)

`resolve_code`가 **관리코드 → `박스매입단가`**를 base로 잡고 `매입가 = base × N`.
선물세트는 1세트·박스 리스팅이 **같은 관리코드**를 쓰므로, **박스가 N=1이고 그보다 작은 단위에 분수 N**이 들어간다.
(직관과 반대 — "박스니까 N=박스내품"이 아니다)

**N = 리스팅의 세트수 ÷ 박스내품**

| ESM | `ref` | `hapo_multiplier.csv` | **마스터상품번호**(등록결과 export 첫 컬럼) |

## §15. 앱 이관 — 선물세트 시즌 관제판 (2026-09-07)

구 VBA 워크북 `스마트스토어_마진율_계산기_V12.xlsm` **`선물세트` 시트**(sheet17, 34행 × A~Z)를
Streamlit 페이지로 이관했다. 시즌 한정 트랙이라 앱 미개발이었으나 사용자 요청으로 착수.

### 자산
| 자산 | 위치 |
|---|---|
| 코어 | `core/intelligence/giftset_season.py` |
| 페이지 | `app/pages/14_선물세트시즌.py` (네비 첫 그룹) |
| 시즌 파라미터 | `reference/giftset_season.json` — **명절마다 이 파일만 교체** |

### 구 시트에서 바로잡은 것 (원문대로 옮기면 안 되는 이유)
1. **N열(11번가) SUMIFS 3번째 인자가 행마다 엉뚱한 셀**(r3=`B16`·r4=`B19`…) + **`#REF!` 2건**.
   값이 전부 0이라 티가 안 났다.
2. **D열 유통기한** = `XLOOKUP(…선물세트목록!AB:AB…)` 인데 **AB는 빈 열**(실제는 AC·AD) → 전건 0.
   **사용자 결정 = 버림.**
3. H·I·U가 행마다 수식/값 뒤섞임(대부분 값으로 굳어 재계산 안 됨).
4. **W~Z 단위 붕괴** — 이름은 '판매량/판매박스'인데 SUMIFS가 잡는 건 **판매금액**.
   `Y = X/F`(당일매출÷박스매입가)는 박스수가 아니다. → **수량(세트) 기반으로 재구축.**
5. 45-12-06 r10·r11 중복. 6. 라인업 34행 고정(구 코드 5종 잔존·현행 13종 누락).
7. 채널 낡음(멸치·11번가 사장, **자사몰 없음**). 8. 이익·마진 축 부재.

### 설계 (사용자 확정 2026-09-07)
- **행 = 자동 산출**: `유니버스 ∩ (박스재고>0 ∪ 시즌매출>0)`,
  유니버스 = `product_attributes.최종분류=='선물세트'` **∪** `giftset_lineup_2026.csv`.
  ★한쪽에만 있는 코드에 `결손` 플래그 → **기준데이터 구멍 탐지기 겸용**(2026-08-27 3종 누락 전례).
  → 노드 `line` 의 "product_attributes 기반 유니버스는 쓰지 않는다"는 **합집합 + 결손 플래그로 대체**.
- **축 4종**: 채널별 매출 · 채널별 이익/마진 · 수량(세트) 소진예측 · 작년 YoY(달력·영업일 병기).
- **탭 5**: 진도판 / 관제판 / 재고 경보 / 가격변경(cmm 빌더 재사용) / 데이터 적재(`store.ingest`).
- **최신 매출** = 업로드 → 파케이 자동 적재. `date_range_replace`라 부분 기간도 안전.
- **노출 상시**, 비시즌(D > 시즌창 또는 D < −15)엔 안내문만.

### 핵심 규칙 (코어에 박제)
- **채널군** = 오픈마켓 / 리테일 / 자사몰 / 나들 / 오프라인. `쿠팡(로켓창고)`는 위탁재고라 전 집계 제외.
  ★**`태동마트 자사몰`이 ERP 상호명에 실재함 확인** — 2026-08-04부터 이월된 "자사몰 매출이 ERP에
  없다" 미확인 항목 **해소**(시즌 선물세트 자사몰 매출 637만).
- **영업일 YoY** = 작년 같은 순번 영업일의 **달력 날짜까지 주말 포함 누적**(평일 필터 후 cumsum 금지).
- **판정** = §6 4분면. **작년 실적 없는 신규 코드는 YoY가 없으므로 '미달' 단정 대신 시즌 전체
  밴드 판정을 승계**한다. 재고 ≤0은 재고부족 쪽, 소진예측은 0 클램프.
- **이월 위험** = `마감후잔여세트 = max(세트재고 − 일평균세트7 × 잔여일, 0)`, 잔여일 = D − 마감D(5).

### §15-B 후속 ② — 판정 수치화·표시 규칙 (2026-09-08)

**판정만으로는 못 움직인다.** "추가매입 검토"가 얼마를, "인상 검토"가 몇 %를 뜻하는지 없으면
결국 사람이 다시 계산해야 한다. → `core.prescribe()` 가 **전부 산술로** 수치와 근거를 만든다.

| 판정 | 수치 | 식 |
|---|---|---|
| 🔴 인하 | 마진 −Δ%p → 가격 −x% | `Δ = min(마진 − 3%, 이월비용률 3.3%p) × min(k−1, 1)` · `k = (재고/잔여일) ÷ 일평균` |
| 🔵 인상 | 마진 +Δ%p → 가격 +x% | `Δ = (계획마진 8.8% − 현재마진) × 0.5 × (1 − 소진예측일/잔여일)` |
| 🟡 추가매입 | +N세트(B박스)·매입액 | `N = 일평균 × 잔여일 − 재고` |
| 🟢 유지 | 이월 예상 / **촉진 인하** | 마감후잔여세트. 촉진 대상이면 🔴와 같은 식으로 인하폭 산출 |

- 상한 근거 = **이월비용률(§7)**, 하한 = **절대하한 3%**, 인상 앵커 = **계획마진**,
  절반스텝 = 두뇌④(ADR 0026). 가격 환산 = `Δp/p = (1−m)/(1−m′) − 1`(원가 고정).
- **상태를 존중한다** — `판매중지`·`추가입고없음`·재고 ≤ 0 이면 가격/매입 권고를 만들지 않고
  왜 안 되는지를 문장으로 돌려준다.
- ★ **🟢 유지 + 재고 과잉 + 촉진**이 가장 중요한 조합이다. 4분면만으로는 "유지"가 나오지만
  이월 물량이 쌓인다(T12호 마감 후 1,356세트·3,580만). 촉진 플래그가 이 구멍을 연다.

**표시명(`DISPLAY_NAMES`)** — 내부 컬럼명은 그대로 두고 화면·엑셀에서만 치환:
`작년동기_달력`→작년 이맘때까지 · `YoY`→작년 이맘때 대비 · `작년시즌`→작년 시즌 전체 ·
`작년진도`→작년 전체 대비 · `마감후잔여세트`→마감후잔여세트(예상).

**★ `미분류` 열 신설** — `시즌매출`은 미분류를 포함하는데 채널 열에 칸이 없어
**5억 5,505만이 표에서 조용히 사라지고 있었다**(2026-09-08 실측). `channel_columns()` 에
`GRP_UNK` 를 넣어 **채널합 == 시즌매출**이 되게 했다. 미분류가 크면 `마진율`·`YoY`·`판정`이
전부 그만큼 오염되므로, **미분류 열이 크면 먼저 화이트리스트부터 채운다.**

**엑셀 서식(사용자 정제본 2026-09-08 기준)** — 금액=회계 서식(쉼표·음수 −·0은 `-`) ·
마진율 `0.0%` · YoY류 `0%` · 수량 `#,##0` · 코드 텍스트 · 헤더 볼드+음영 · 틀고정 A2 · 자동필터.


### §16 후속 — 인터넷사업부 export = 매출이 아니라 **분류 사전** (2026-09-08)

사용자: "온라인 b2b는 자주 매출나오는 온라인채널+나들 외에 1회성처럼 보이고 따로 관리 안 하는
채널은 다 온라인 b2b야. **지금은 그걸 찾기 어렵고, 내가 인터넷 사업부쪽 매출만 뺄 수 있음.**"

**딜레마** — 파케이(`master/sales_*.parquet`)는 **전사로 유지해야 한다**(대시보드·재고지능·
두뇌 전부가 같은 파일을 쓴다). 사업부 export를 적재하면 그 구간 오프라인이 삭제된다
(2026-09-07 실사고, 적재 탭에 🚫 가드 있음). 그렇다고 전사만 쓰면 **미분류가 계속 쌓인다.**

**해법 = 사업부 export를 소속 판정의 오라클로만 쓴다.** 적재하지 않는다.

| 조건 | 판정 |
|---|---|
| export 에 있고 표기 규칙(오픈마켓·자사몰·나들·제외)으로 안 잡힘 | **온라인B2B** |
| **같은 기간** 전사 파케이엔 있는데 export 엔 없음 | **사업부밖**(오프라인 확정) |
| 표기 규칙으로 이미 잡힘 · 화이트리스트에 이미 있음 | 후보에서 제외 |

- 2026-09-07 에 손으로 69곳을 만들 때 쓴 논리와 같다. 이제 **export 한 장이면 그 기간 분류가
  전부 채워진다** — 매 시즌 새로 생기는 1회성 상호명을 사람이 찾을 필요가 없다.
- **기간이 겹쳐야 성립한다.** export 가 못 덮는 구간은 판정 근거가 없으므로 대상에서 뺀다.
- ⚠️ **전사 export 를 여기 올리면 오프라인이 통째로 온라인B2B 로 편입된다** →
  거래처 수가 같은 기간 파케이의 95% 이상이면 경고를 띄운다.
- 위치 = 데이터 적재 탭 **②번 섹션**(①전사 적재와 물리적으로 분리).

**운영 순서** — ① 전사 영업이익현황을 파케이에 적재 → ② 같은 기간 사업부 export 로 분류를 채움.
②를 하고 나면 `미분류` 열이 0 이 되고, `마진율`·`YoY`·`판정`이 사업부 스코프로 정확해진다.

### §15-B 후속 ④ — 발주량 산출 (2026-09-08)

소진 임박 경보가 "얼마나 발주?"로 이어지도록 재고 경보 탭에 넣었다. **단위는 박스.**

`일평균(박스) = 최근 N일 판매세트 ÷ N ÷ 박스내품` ·
`N일안 = ⌈일평균 × 단기일수 − 박스재고⌉` · `전체필요 = ⌈일평균 × 잔여시즌일 − 박스재고⌉`

  **재고는 채널 공용**이라 오프라인 수요도 같은 재고에서 빠진다.
  실측 `45-05` 사업부 비중 22% → 사업부 기준 5일안 0박스 vs 전사 기준 271박스.

- ★ 집계는 **원본 매출 프레임에서 다시 분류**한다. `scope_sales` 결과는 `사업부밖`이 빠져 있어
  '전사 기준'을 만들 수 없다.
- ★ **주말이 창에 끼면 평균이 낮게 잡힌다**(올해 주말 온라인 0). `평균 산출 일수`를 줄여 확인할 것.

- **발주 전 시즌 생산 마감·입고 리드타임 확인이 선행**한다. 생산이 닫혔으면 숫자는 무의미하고

## 핵심 수식
합계 = 공급가 × 수량 + ceil(수량 / 최대합포수량) × 배송비
- VBA 원식: `F2 = E2*C2*B2 + G2` → 합계 = 공급가 × 수량 × 합포 + 배송비나누기 × 배송비기본.
- 최대합포수량 = SKU!F열 (배송비 부과 규칙). 코카콜라500=1, 일반음료=2~3.
- 배송비나누기 N = ROUNDUP(수량 / 최대합포수량) = `math.ceil(qty / max_bundle)`. 배송비는 합포수량 초과 시 1배송당 1회 추가.
- 골든 15행 전수 역추적 후 구현.

## 출력 방식 (2026-06-04 수정)
- **zipfile 직접 조작**: 원본 xlsx를 zipfile로 열어 `sheet1.xml`의 합계 열만 패치 후 저장.
- 기존 방식(`shutil.copy2` + openpyxl save)은 모든 문자열 셀을 sharedString(`t="s"`) → inlineStr(`t="inlineStr"`)으로 변환 → 외부 시스템 헤더 인식 불가 문제 발생하여 교체.
- zipfile 방식은 sharedStrings.xml 구조를 원본 그대로 유지. 헤더 및 모든 문자열 셀 `t="s"` 보존.

## 전용 함정
- **openpyxl read_only 셀 값은 숫자도 str로 읽힐 수 있음** → `int()` 명시 변환 필수.
- **SKU 테이블 동일 관리코드 중복 존재** (예: 23-18 × 2) → `drop_duplicates('관리코드', keep='first')` 필수.
- 우편번호는 입력 xlsx에 이미 문자열 `"08206"` 형태로 저장 → 별도 처리 불필요.
- **★ openpyxl save 금지**: `_save`에서 openpyxl의 `Workbook.save()` 사용 시 sharedString → inlineStr 변환 발생. 합계 열 수정은 반드시 zipfile 직접 조작 방식 사용. (2026-06-04 확인)
- **★ zipfile 패치는 빈 합계 셀을 못 잡는다 (값 누락·행손상)**: 합계 열 패치를 `<c r="G2">...</c>` 정규식으로만 하면, 신선한 템플릿의 **빈 합계 셀**(자체닫힘 `<c .../>` 또는 셀 자체 없음)을 처리 못 함. 자체닫힘이면 `.*?</c>`가 다음 행까지 과매칭해 데이터 손상, 셀 없으면 값 누락. `_patch_column_values`는 ① 값셀·자체닫힘 둘 다 템퍼드 정규식으로 매칭 치환, ② 셀 없으면 `_insert_cell_into_row`로 열 순서 지켜 삽입해야 함. 골든이 "이미 값 있는 파일"이면 이 회귀를 못 잡으니 **빈 G셀 fixture 필수**. (2026-06-05 픽스 — logs/2026-06-05-onnuri-empty-gcell-fix)

- **★ SKU 일부만 미매칭이면 NaN 으로 전체 실행이 죽었다 (2026-08-04 픽스)**:
  `_calc` 는 미매칭 행에 `None` 을 돌려주는데, 같은 컬럼에 정수가 하나라도 섞이면
  pandas 가 float64 로 추론하며 **None → NaN**. `_patch_column_values` 가드가
  `val is None` 만 봐서 NaN 이 통과 → `int(nan)` ValueError.
  ★ **전건 미매칭이면 object dtype 이라 안 터진다** — "일부만 미매칭"일 때만 터지는 구멍이었음.
  → 가드를 `val is None or (isinstance(val,float) and math.isnan(val))` 로. 미매칭 행은
  합계 빈칸으로 남기고 나머지는 정상 출력한다.
- **★ 관리코드 양쪽 정규화**: `LoadSKU`(SKU표) 와 `_calc`(발주서) 둘 다 `core.base.clean_cell`
  적용. 참조 CSV 에 붙여넣기 개행이 섞여 들어와도 매칭되게 하는 방어층
  (근본 처방은 저장측 `sanitize_ref_df` — pitfalls 참조).
- **발주서 관리코드 단위 주의**: 낱개로 파는 건은 발주서에 **PC낱개 코드**로 와야 한다.
  2026-08-04 밀리원 삼계탕이 박스코드 `94-38-01` 로 들어와 미매칭 → 사용자가 발주서를
  `PC005982` 로 정정. SKU표는 PC코드가 관리코드, 박스코드는 `원코드` 열에 둔다.

## 선물세트 공급가 책정 규칙 (2026-07-29 확립)
- **제이티유통 = 명절 전용 거래처.** 매출 발생이 명절 분기에만 있음(2026-01·02만, 3~6월 0).
  추석/설 앞두고 연락 오면 **선물세트 재고 ↔ 단가표 등재 대조**부터 하는 게 표준 진입.
- 선물세트 정의 = `product_attributes.csv` 식품음료=='선물세트'(65종). 재고 판정은
  `product_master.csv` **박스** 컬럼(>0). 세트 수 = 박스×박스내품 + 낱개.
- **단위 = 1세트.** 공급가·배송비 부과기준 모두 세트 기준이고, `배송비 부과 규칙` = **박스내품**과
  일치(전건). 예외 2건: 50-20-01·50-21-01 김식탁은 **박스(3세트) 단위 등재**라 규칙=1.
- **마진 규칙**: 세트매입 = 박스매입단가 ÷ 박스내품.
  공급가 = `ceil(세트매입 / (1 − 목표마진) / 100) × 100`.
  목표마진 = **max(기준마진율 중앙값, 6.5%)**, 단 **대량재고 품목은 5.5%**(회전 우선).
  - 6.5% 근거 = 기존 등재분 실측 마진율 중앙값(범위 4.8~9.3%).
  - JT는 **수수료 0 + 배송비 3,000 별도청구**(실 택배 2,700 → +300) → 온라인 채널(수수료 6~17.5%
    + 택배 흡수)과 같은 마진율이어도 실이익이 큼. 그래서 기준마진율보다 위에서 잡아도 경쟁력 있음.
- ★ **VAT 기준**: `공급가(VAT 포함)` ↔ product_master 매입단가를 **동일 기준으로 직접 비교**한다.
  기존 등재분 전건이 이 기준에서 +5~9%로 일관(다른 기준이면 전건 역마진). 식봄·리테일 공식과 동일 관행.

## `운영` 컬럼 (2026-07-29 신설)
- sku_list.csv 맨 끝 컬럼. **O=판매중(운영 가능) / X=판매중지 / `-`=미판정**.
- 배경: 단가표에 있어도 저쪽에서 **판매중지 상태면 주문이 안 들어옴** → 무엇을 재개시킬지
  우리가 알려줘야 함. 이 컬럼이 "저쪽에 재개 요청한 상태"의 기록.
- 현재 채움 범위 = **선물세트 32행만**(O 23 / X 9). 소분·일반 88행은 `-`.
- ★ `onnuri_order.py`는 sku_list를 **컬럼명으로만** 참조하므로 컬럼 추가·순서 변경은 무해.
  단 신규 컬럼은 **맨 끝에** 붙일 것(기준데이터관리 SKU단가표 탭 렌더링도 그대로 통과).
- 갱신 트리거: 재입고로 재고 0→양수 / 소진으로 양수→0 시 O·X 재판정 + 저쪽에 통보.

# workflows/hanjin-individual-shipping.md — 한진택배 개별발송 (개별송장 출력)

> **성격**: 챗 네이티브 · 앱 미탑재. 채널 주문(이지어드민 송장처리)과 **별개 경로**.
> 선물세트 시즌에 B2B·지인·단체 등 **채널 밖 개별 요청**이 늘면서 상시화된 업무.
> 기존 `invoice-fill`(송장처리)은 채널 주문에 송장번호를 **되채우는** 업무 — 이건 반대로
> 주문 정보로 **접수 양식을 만들어 올리고 송장번호를 받아오는** 업무다. 혼동 금지.

## 0. 한눈에 흐름

```
사용자: 상품·세트수 + 받는분(성명·전화·주소)
        ↓  ① 주소·우편번호 검증 (필수·실패 시 중단하고 되묻기)
        ↓  ② 행 분할  = ceil(세트수 ÷ 박스내품)
        ↓  ③ 한진 접수 양식(21열) 생성
사용자: 한진에 업로드 → 송장번호 붙은 "재출력 세부내역" 받아서 전달
        ↓  ④ 수량 대조 + 분할 검증
        ↓  ⑤ 6열 정제본 반환 (받는사람 배포용)
```

## 1. ★ 핵심 규칙 — 1행 = 송장 1장

**한 행에 송장 1개**. `P 박스수량`을 키워도 한진은 송장 1장으로 묶으므로,
**용량 초과분은 같은 주소로 행을 복제**해야 송장이 2장 나온다.

```
행수        = ceil(주문세트수 ÷ 박스내품)
행별 세트수  = min(박스내품, 잔여)
P 박스수량   = 1        (항상)
```

- **기준 단위 = 세트**(박스가 아니다). `(box/3)`은 **한 송장에 실을 수 있는 최대 세트수**.
- **최대 세트수 = `product_master.박스내품`** (사용자 확정 2026-08-25). 별도 관리표 불필요.
- 예: G호(박스내품 3) 7세트 → `3 + 3 + 1` = **3행**, 마지막 행 품목명 `G호 (box/3) 1세트`.
- ★ 선물세트는 `product_attributes.합포수량`이 **전건 1**이라 결과가 같지만,
  **판단 근거는 박스내품**이다(합포수량으로 나누면 일반 상품에서 틀림).

## 2. 품목명 문법 (O열)

```
{약칭} (box/{박스내품}) {이 행의 세트수}세트
```
예 — `G호 (box/3) 3세트` · `애경마음14호 (box/6) 4세트` · `동원참치18호 (box/3) 3세트`

- **약칭은 사용자가 부르는 호칭을 그대로 쓴다.** `product_master` 상품명
  (`CJ 복합스페셜 G호/3세트(BOX)(20)`)은 그대로 못 쓴다.
- ★ **자동 추출 금지.** `…N호` 패턴으로 뽑으면 37종 중 32종은 나오지만 **충돌이 생긴다**:
  `1호` = 45-08(CJ스팸1호) ∩ 45-11(CJ스팸복합1호) / `S호` = 01-19-10 ∩ 45-09-01.
  둘 다 재고가 실해서 실제로 오출고 위험. 게다가 브랜드 없이 숫자만 남는 게 14종.
  → **사용자가 준 호칭을 받아쓰고, 못 받았으면 되묻는다.**

## 3. 양식 (한진 접수 · 21열)

★★ **자산 위치(2026-08-31 박제)**: `work-automation-app` → `reference/hanjin_shipping_template.xlsx`
(= `_3-b_한진_sample.xlsx` 원본 바이트, 10,697 bytes, md5 `51ea005e5bd2bf821d6044391838dc44`).
**더 이상 사용자에게 재요청하지 말 것.** raw 받아 `openpyxl`로 열고 샘플 데이터행(2행) 삭제 후 기입.

`Sheet1` · 헤더 1행 · **데이터 2행부터** · 병합/수식/유효성검사 없음(자동필터 `A1:U1`만).
**헤더 21열 전부 텍스트(`@`) 서식.** 샘플 데이터행 1개 포함(홍길동 → 정상, `G호 (box/3) 3세트`) — **삭제하고 쓸 것.**

**헤더 문자열(정본, 순서대로)**
`예약구분` · `집하예정일` · `보내는분성명` · `보내는분전화번호` · **`보내는분기타연락처`** ·
`보내는분우편번호` · `보내는분주소(전체, 분할)` · `받는분성명` · `받는분전화번호` · **`받는분기타연락처`** ·
`받는분우편번호` · `받는분주소(전체, 분할)` · `운송장번호` · `고객주문번호` · `품목명` · `박스수량` ·
`박스타입` · `기본운임` · `배송\n메세지1`(줄바꿈 포함) · `배송\n메세지2` · `운임구분`

⚠️ G·L 헤더는 `보내는분주소`가 아니라 **`보내는분주소(전체, 분할)`**, S·T는 **개행 문자 포함**.
열 접근은 인덱스 하드코딩 대신 **헤더명→열번호 dict**로 할 것.

| 열 | 항목 | 값 |
|---|---|---|
| C | 보내는분성명 | **(주)태동유통판매** 고정 |
| D | 보내는분전화번호 | **010-6291-9345** 고정 |
| F | 보내는분우편번호 | **12963** 고정 |
| G | 보내는분주소 | **경기도 성남시 분당구 탄천상로 163번길 20, 1층 판교대리점** 고정 |
| H | 받는분성명 | 사용자 |
| I | 받는분전화번호 | 사용자 — **필수. 없으면 되묻는다** |
| K | 받는분우편번호 | 검증으로 자동 확보 |
| L | 받는분주소 | 사용자(도로명 정식표기로 보정) |
| O | 품목명 | §2 문법 |
| P | 박스수량 | **항상 1** |
| S | 배송메세지1 | 배달장소 메모 등(있을 때만·전 행 반복) |

- 비우는 칸: A예약구분·B집하예정일·E보내는분기타연락처·J받는분기타연락처·M운송장번호(한진 회신)·N고객주문번호·
  Q박스타입·R기본운임·T배송메세지2·U운임구분.
- **우편번호(F·K)는 텍스트 서식 필수** — `01909`가 숫자로 들어가면 `1909`로 뭉개진다.
- 보내는분 고정값은 **사용자가 따로 말하지 않는 한 그대로** 사용.

## 4. ★ 주소 검증 (필수 단계)

사용자 지시로 **반드시** 수행. 생략 금지.

1. 도로명+건물번호를 조회해 **실재 확인** → 미조회면 진행 중단하고 되묻기.
2. **우편번호를 확보해 F·K에 기입.** 파싱 실패 위험이 줄어든다.
3. 동/호 등 상세주소는 검증 대상 아님(사용자 값 그대로).
4. 시/도 약칭은 정식표기로 보정(`서울시` → `서울특별시`).

**검증 실적 (2026-08-25)**

| 입력 | 결과 | 우편번호 |
|---|---|---|
| 서울특별시 노원구 마들로 111 월계시영고층아파트 | ✅ 미륭·미성·삼호3차 3,930세대·32동 | 01909 |
| 경기도 의정부시 신곡로 36 삼익한일아파트 101동 | ✅ 한일·삼익아파트(상세건물명 101~106동) | 11731 |

- 건물명은 소스마다 다를 수 있다 — 도로명주소 공식 `한일· 삼익아파트`(가운데점) vs
  카카오맵 `삼익한일아파트`. **도로명+번지가 정확하면 통과**된다(실증).
- ★ **추정 우편번호를 넣지 말 것.** 보내는분 우편번호를 인접 번지(탄천상로163번길 10 = 13636)에서
  추정해 넣었는데 한진이 주소로 재조회해 **12963**으로 잡았다. 추정치는 틀린다.

## 5. 회수 파일 검증 (한진 "재출력 세부내역")

시트 `상세내역` · **2단 헤더(1~2행 병합)** · **데이터 3행부터** · 48열.

| 열 | 항목 | | 열 | 항목 |
|---|---|---|---|---|
| D(4) | 운송장번호 | | Z(26) | 받는분 주소 |
| M(13) | 보내는분 이름 | | AC(29) | 수량 |
| N(14) | 보내는분 연락처 | | AJ(36) | 특기사항(= 보낸 S 배송메세지1) |
| R(18) | 보내는분 우편번호 | | AK(37) | 품목명 |
| T(20) | 받는분 이름 | | AP(43) | 내품명1 |
| Y(25) | 받는분 우편번호 | | | |

**검증 2종 (필수)**
1. **수량 대조** — (받는분 우편번호 × 약칭)별 세트 합계 = 당초 주문. 주문에 없는 항목 0.
2. **분할 검증** — 품목명의 `(box/N)`이 `product_master.박스내품`과 일치하고,
   행 수 = `ceil(주문세트 ÷ N)`, **N 초과 행 0**.
- 부수 확인: 운송장번호 중복 0 · `AC 수량` 전건 1.

★ **개인정보 마스킹**: M·N·Z·U 등이 별표 처리되어 내려온다
(`(주)태동유통판*` · `0106291****` · `서울특별시 노원구 마들로 111 ****`).
받는사람 배포용으론 무해하나, **보내는분 정보는 우리 원본값으로 되살릴 수 있다**(요청 시).

## 8. 함정

- **`P 박스수량`을 키우면 송장이 안 늘어난다.** 반드시 행 복제.
- **기준은 세트, 나누는 수는 박스내품.** 합포수량으로 나누면 일반 상품에서 어긋난다
  (선물세트는 합포수량 1이라 우연히 같아 보임 — 여기에 속지 말 것).
- **약칭 자동 추출 금지**(§2 충돌).
- **우편번호는 텍스트 서식**(앞자리 0 소실).
- **추정 우편번호 기입 금지**(§4).
- 회수 파일은 **3행부터**가 데이터(2단 헤더). 1행만 헤더로 보면 서브헤더가 데이터로 섞인다.
- 받는분 **전화번호 없이 진행 금지** — 사용자 지시. 무조건 되묻는다.

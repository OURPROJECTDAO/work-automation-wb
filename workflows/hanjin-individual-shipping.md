# workflows/hanjin-individual-shipping.md — 한진택배 개별발송 (개별송장 출력)

> **성격**: 챗 네이티브 · 앱 미탑재. 채널 주문(이지어드민 송장처리)과 **별개 경로**.
> 선물세트 시즌에 B2B·지인·단체 등 **채널 밖 개별 요청**이 늘면서 상시화된 업무.
> 기존 `invoice-fill`(송장처리)은 채널 주문에 송장번호를 **되채우는** 업무 — 이건 반대로
> 주문 정보로 **접수 양식을 만들어 올리고 송장번호를 받아오는** 업무다. 혼동 금지.

## 0. 한눈에 흐름

```
사용자: 상품·세트수 + 받는분(성명·전화·주소)
        ↓  ① 주소·우편번호 검증 (필수·실패 시 중단하고 되묻기)
        ↓  ② 행 분할  = ceil(세트수 ÷ 박스내품)
        ↓  ③ 한진 접수 양식(21열) 생성
사용자: 한진에 업로드 → 송장번호 붙은 "재출력 세부내역" 받아서 전달
        ↓  ④ 수량 대조 + 분할 검증
        ↓  ⑤ 6열 정제본 반환 (받는사람 배포용)
```

## 1. ★ 핵심 규칙 — 1행 = 송장 1장

**한 행에 송장 1개**. `P 박스수량`을 키워도 한진은 송장 1장으로 묶으므로,
**용량 초과분은 같은 주소로 행을 복제**해야 송장이 2장 나온다.

```
행수        = ceil(주문세트수 ÷ 박스내품)
행별 세트수  = min(박스내품, 잔여)
P 박스수량   = 1        (항상)
```

- **기준 단위 = 세트**(박스가 아니다). `(box/3)`은 **한 송장에 실을 수 있는 최대 세트수**.
- **최대 세트수 = `product_master.박스내품`** (사용자 확정 2026-08-25). 별도 관리표 불필요.
- 예: G호(박스내품 3) 7세트 → `3 + 3 + 1` = **3행**, 마지막 행 품목명 `G호 (box/3) 1세트`.
- ★ 선물세트는 `product_attributes.합포수량`이 **전건 1**이라 결과가 같지만,
  **판단 근거는 박스내품**이다(합포수량으로 나누면 일반 상품에서 틀림).

## 2. 품목명 문법 (O열)

```
{약칭} (box/{박스내품}) {이 행의 세트수}세트
```
예 — `G호 (box/3) 3세트` · `애경마음14호 (box/6) 4세트` · `동원참치18호 (box/3) 3세트`

- **약칭은 사용자가 부르는 호칭을 그대로 쓴다.** `product_master` 상품명
  (`CJ 복합스페셜 G호/3세트(BOX)(20)`)은 그대로 못 쓴다.
- ★ **자동 추출 금지.** `…N호` 패턴으로 뽑으면 37종 중 32종은 나오지만 **충돌이 생긴다**:
  `1호` = 45-08(CJ스팸1호) ∩ 45-11(CJ스팸복합1호) / `S호` = 01-19-10 ∩ 45-09-01.
  둘 다 재고가 실해서 실제로 오출고 위험. 게다가 브랜드 없이 숫자만 남는 게 14종.
  → **사용자가 준 호칭을 받아쓰고, 못 받았으면 되묻는다.**

## 4. ★ 주소 검증 (필수 단계)

사용자 지시로 **반드시** 수행. 생략 금지.

1. 도로명+건물번호를 조회해 **실재 확인** → 미조회면 진행 중단하고 되묻기.
2. **우편번호를 확보해 F·K에 기입.** 파싱 실패 위험이 줄어든다.
3. 동/호 등 상세주소는 검증 대상 아님(사용자 값 그대로).
4. 시/도 약칭은 정식표기로 보정(`서울시` → `서울특별시`).

**검증 실적 (2026-08-25)**

| 입력 | 결과 | 우편번호 |
|---|---|---|
| 서울특별시 노원구 마들로 111 월계시영고층아파트 | ✅ 미륭·미성·삼호3차 3,930세대·32동 | 01909 |
| 경기도 의정부시 신곡로 36 삼익한일아파트 101동 | ✅ 한일·삼익아파트(상세건물명 101~106동) | 11731 |

- 건물명은 소스마다 다를 수 있다 — 도로명주소 공식 `한일· 삼익아파트`(가운데점) vs
  카카오맵 `삼익한일아파트`. **도로명+번지가 정확하면 통과**된다(실증).
- ★ **추정 우편번호를 넣지 말 것.** 보내는분 우편번호를 인접 번지(탄천상로163번길 10 = 13636)에서
  추정해 넣었는데 한진이 주소로 재조회해 **12963**으로 잡았다. 추정치는 틀린다.

## 7-B. ★ 오류 재접수 (반려분 수정)

한진 업로드 시 일부 행이 반려되면 `엑셀오류_YYYYMMDD_HHMMSS.xlsx` 가 떨어진다.

**오류 파일 구조** — 시트 `sheet1` · **헤더 1행** · 데이터 2행부터 · 22열.
`1 보내는 분` `2 전화번호` `5 우편번호` `6 주소` `7 받는 분` `8 전화번호` `12 주소`
**`13 주소수정`** `14 수량` `15 품목명` `19 특기사항` `20 메모1` **`22 오류메시지`**.
→ **`13 주소수정` 칸이 고쳐진 주소**. 여기 값으로 갈아끼운다.

**★ 재접수는 전체 배치를 다시 올린다 — 반려 행만 따로 올리는 게 아니다.**
원본 접수본을 그대로 복사해 **해당 행만 제자리 수정**하고 68행 전체를 재업로드한다.
(반려 3행만 담은 파일을 올리면 나머지 65행 송장이 안 나온다. 2026-09-02 실제로 이 오해를 했다.)

**절차**
1. 원본 접수본을 `shutil.copy` → 사본에서 `받는분성명` 매칭으로 해당 행 전화·주소·우편번호 갱신.
2. 배송메모 등 전 행 공통 변경이 있으면 같이 적용.
3. **셀 단위 diff 검증** — 변경 셀 수가 의도한 수와 정확히 일치하고, 그 외 전 셀이 원본과 동일한지 확인.
4. 재회수 후 §5 검증 2종 + 반려 행이 실제로 발행됐는지 개별 확인.

**⚠️ 오류파일 `주소수정` 칸이 `주소` 칸과 동일할 수 있다.**
2026-09-02 와이엠에너지가 그랬는데, 화면상 "수정 안 됨"으로 보이지만
**8/31 원본과 비교하면** 도로명(`공수1길`→`공수골1길`)·호수(`102호` 삭제)·전화 뒷자리(`7674`→`7464`)가
이미 바뀌어 있었다. **오류파일 단독으로 판단하지 말고 반드시 원본 접수본과 3자 대조**할 것.

**⚠️ 오류파일의 행 수가 실제 반려 건수와 다를 수 있다.**

## 8. 함정

- ★ **주문 단위가 "세트"가 아니라 "박스"로 올 수 있다**(2026-08-31 첫 사례). 그대로 행수로 쓰면
  8행이 아니라 8세트로 오해한다. **반드시 세트로 환산**: `세트수 = 박스수 × product_master.박스내품`.
  환산 결과가 박스내품으로 정확히 나눠떨어지면 `행수 = 박스수`가 되어 우연히 같아 보이지만,
  나눠떨어지지 않는 경우를 위해 공식을 거치는 습관을 유지할 것.

- **`P 박스수량`을 키우면 송장이 안 늘어난다.** 반드시 행 복제.
- **기준은 세트, 나누는 수는 박스내품.** 합포수량으로 나누면 일반 상품에서 어긋난다
  (선물세트는 합포수량 1이라 우연히 같아 보임 — 여기에 속지 말 것).
- **약칭 자동 추출 금지**(§2 충돌).
- **우편번호는 텍스트 서식**(앞자리 0 소실).
- **추정 우편번호 기입 금지**(§4).
- 회수 파일은 **3행부터**가 데이터(2단 헤더). 1행만 헤더로 보면 서브헤더가 데이터로 섞인다.
- 받는분 **전화번호 없이 진행 금지** — 사용자 지시. 무조건 되묻는다.
- ★ **수량이 같다고 같은 품목이 아니다.** 2026-09-02 5차가 3차와 "8박스 40세트"로 완전히 동일했으나
  실제 품목은 45-11 → 45-18-02 로 달랐다. 직전 건과의 유사성은 추정 근거가 될 수 없다.
- ★ **박스내품 5짜리 선물세트가 6종이라 "스팸 N박스"만으론 특정 불가.** 되묻는 게 정상 절차다.
- ★ **반려분만 따로 올리지 말 것** — 전체 배치를 다시 올린다(§7-B).
- **우편번호는 없어도 통과할 수 있다.** 2026-08-31 태성전기 68행은 `받는분우편번호`가 **전건 공란**이었는데
  65건이 정상 발행됐다(반려 3건은 우편번호가 아니라 **주소 자체** 문제). 즉 §4의 우편번호 확보는
  실패율을 낮추는 보조 수단이고, **추정치를 넣느니 비우는 게 낫다**(§4 추정 금지와 일관).

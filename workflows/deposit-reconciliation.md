# deposit-reconciliation (입금 대사 — 은행 ↔ 천년경영 ERP)

> 상태: 운영중 (챗 네이티브 · 매달 반복 가능 · 앱 미탑재)
> 최초: 2026-07-14. 목적 = 총액이 아닌 **거래처(채널) 오분류 탐지**.

## 배경 / 왜
오픈마켓 정산 수취계좌(398-075486-01-018)에 실제 입금된 내역을, 천년경영 ERP에
사람이 수기 등록한 입금전표와 대사한다. 은행내역을 보고 "어느 거래처(채널) 정산인지"를
사람이 지정하므로 **총액은 항상 맞고**(같은 소스), 리스크는 **개별 건이 엉뚱한 거래처로
등록되는 오분류**뿐이다. 대사의 본질 = 오분류 색출.

## 입력 파일
1. 은행 거래내역: `거래내역조회_입출식_예금N-M월.xlsx` (헤더 3행째)
   - B=거래일시(datetime) · D=입금 · **F=거래내용**(수기·거래처 식별력 高)
     · M=상대계좌예금주명(PG 법인명·식별력 低)
2. ERP 입금전표: `Exp..._입금전표관리__N-M월_.xlsx` (Sheet1)
   - 거래일자 · 거래처명 · 거래처명(약칭) · **결제금액** · 결제방법(전건 '통장') · 자료등록일시

## 핵심 원칙 (사용자 확정)
1. **F열(거래내용) 기준**으로 거래처를 판정한다. M열(예금주명)은 PG 법인명이라
   한 PG가 여러 채널에 걸치면 구분 불가 → 쓰지 않는다.
2. **다수결**: 같은 F값이 ERP에서 압도적 다수로 가는 거래처 = 정답. 소수로 튄 건 = 오분류 의심.
   ("절대 다수가 있는 쪽이 맞는 거래처, 한두 개 실수가 정황상 맞다.")
3. **(주)더즌은 ESM으로만 들어온다** (확정). M열론 더즌이 ESM+마켓보로 섞여 보이나
   F열(주식회사지마켓/옥션)론 전부 ESM. 마켓보로는 은행에 별도 이름으로 안 찍힘
   (F=주식회사마켓/주식회사마켓보로만) → 더즌 입금이 마켓보로일 수 없음.

## 절차
1. **ERP 합계행 제거** — 파일 마지막 행이 거래처명 등 전부 빈칸 + 결제금액만 채운 TOTAL 행.
   제거 안 하면 ERP 총액이 은행의 정확히 2배로 잡혀 완전히 어긋나 보인다(pitfalls TOTAL행 함정).
2. **거래 단위 매칭** — 은행 입금 각 건을 (거래일자, 금액) 완전일치로 ERP 등록건과 짝지음
   (±2~3일 허용). 이름 매핑이 아니라 개별 거래 매칭이라 한 PG가 여러 채널로 갈려도 정확히 추적.
3. **F열 다수결 판정** — 각 F값이 ERP에서 어느 거래처로 갔는지 집계 → 다수=정답, 소수=오분류 의심.
4. **오분류 리스트업** — 소수로 튄 건의 (날짜, 금액, 잘못 잡힌 거래처, 올바른 거래처)를 뽑아
   사용자에게 제시. ERP 정정은 사용자가 직접(전표 거래처만 수정).

## F열 → 천년경영 거래처 매핑 (2026 1~6월 확인분·누적)
| F열 거래내용 | 천년경영 거래처 |
|---|---|
| 스마트스토어정 | 오픈마켓- 스마트스토어 |
| 지마켓 / 주식회사지마켓 / 옥션 | 오픈마켓(ESM/옥션.지마켓.G9) |
| 주식회사마켓 / 주식회사마켓보로 | 오픈마켓- (주) 마켓보로 |
| 쿠팡페이주식회 | 오픈마켓 쿠팡 (윙배송) |
| 한국신용데이터 | 오픈마켓 (주) 한국신용데이터 (캐시노트) |
| 알리익스프레스 / tosspaymen | 오픈마켓- 알리 |
| 제이티유통 | 제이티유통 |
| 우아한형제들 | 오픈마켓- (주) 우아한형제들 (배민상회) |
| 리테일앤인사이트 | 주식회사 리테일앤인사이트 |
| 올웨이즈202601~06 | 오픈마켓- 올웨이즈 |
| (개인/B2B 소액) | F열 그대로 = 거래처명 |

## 실행 이력
- **2026-07-14 (1~6월, v1)**: 은행 1,544건 27.67억 vs ERP 1,537건 27.65억, 차이 184만(0.067%).
  15개 주요 채널 전부 차이 0. F열 다수결 오분류 의심 6건 중 **확정 = F=주식회사지마켓(ESM)
  →마켓보로 3건 8,311,790원**(06-11 4,553,395 / 06-18 3,593,143 / 06-23 165,252).
  사용자 결정: **마켓보로 3건만 ESM으로 정정, 나머지 소액 3건은 그대로.** 로그 2026-07-14-deposit-reconciliation-f-column.

## 함정 / 주의
- ⚠️ **매크로 파일(입금-천년경영_비교_v1.xlsm)은 M열 기준**이라 PG 다채널 오분류를 못 잡음 → F열 방식이 대체.
- ⚠️ 그 매크로 파일은 천년경영입출금 시트 dimension이 1,048,119행으로 부풀어(빈 서식행 100만개)
  44MB·openpyxl 로드 시 메모리 크래시. lxml iterparse로 스트리밍 파싱하거나, 실데이터
  186행 아래를 삭제 후 저장하면 정상화.
- 은행에 마켓보로 이름은 안 찍힘 → 마켓보로 정산은 F=주식회사마켓/마켓보로로만 들어옴.
- 7월 입금이 1~6월 ERP 파일엔 없어 "미대사"로 뜨는 건 기간 밖(정상).

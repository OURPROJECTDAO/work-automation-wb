# cafe24-register (자사몰 카페24 상품 등록)

> 상태: 운영중 (챗 네이티브·앱 미탑재) · 첫 실행 2026-08-20 (추석26 선물세트 43건)
> 관련: channel-margin-monitor(자사몰 모니터·가격변경) · giftset-season-ops(시즌 라인업) · product-registration-common

## 0. 한눈에

카페24 **엑셀(CSV) 상품 대량등록**으로 자사몰에 상품을 올린다. 별도 앱 기능 없음 —
사용자가 카페24 관리자에서 상품목록을 CSV로 내려주면, 그 **양식 그대로** 신규/수정 행을 만들어 돌려준다.

핵심 = **업로드 양식(90열)과 다운로드 양식(88열)이 다른 파일**이라는 것.
- **업로드 양식 = 90열** (`상품 상세설명`·`모바일 상품 상세설명 설정` 등 포함). 정본 = 과거 업로드본.
- **다운로드 = 88열** (상세설명 컬럼 없음). 모니터·상태확인용.
두 양식의 컬럼 순서·이름이 다르므로 **다운로드본을 그대로 고쳐 업로드하면 안 된다.**

## 1. 업로드 양식 — 실제로 채우는 13~15열

90열 중 나머지는 전부 공란으로 두면 카페24 기본설정이 상속된다.

| 컬럼 | 값 | 비고 |
|---|---|---|
| 상품코드 | 공란 | **신규 등록 모드.** 값이 있으면 그 상품 **수정** 모드 |
| 자체 상품코드 | 공란 | |
| 진열상태 / 판매상태 | Y / Y | 재고 없으면 판매상태 N으로 올릴 것 |
| 상품분류 번호 | `62` | 선물세트. 다른 분류는 다운로드에서 확인(`60\|122\|166` 등 파이프 구분 다단계) |
| 상품분류 신상품영역 / 추천상품영역 | N / N | |
| 상품명 | `스팸 8호 1세트` | 규격 빼고 `1세트` 접미. 무료배송판은 뒤에 ` 무료배송` |
| **모델명** | **`[45-21`** | **여는 대괄호 + 관리코드.** 닫는 대괄호 없음(관행) |
| 상품 상세설명 | `<div style="text-align:center;"><img src="…_B1.jpg" … /></div>` | **HTML 필수** |
| 모바일 상품 상세설명 설정 | `A` | PC와 동일 |
| 공급가 | `500000` | **고정 더미.** 등재 전건이 지금도 500000 — 안 쓰는 칸 |
| 판매가 | 실제 판매가 | |
| 최대 주문수량(이하) | 박스내품 × 10 | 기존 39건 중 34건이 예외 없이 이 규칙 |
| **공급사** | `S00000HD` 등 | **§2 참조 — 사실상 배송조건 그룹** |
| 유효기간 사용여부 | `N` | |
| 원산지 | `1800` | |

인코딩 = **UTF-8 BOM + CRLF**(`csv.writer(lineterminator='\r\n')`, `encoding='utf-8-sig'`).
과세구분·제조사 등은 공란으로 두면 카페24가 기본값(`A|10`·`M0000000`)을 넣는다.

## 2. ★ 공급사 = 배송조건 그룹 (핵심)

카페24의 `공급사`는 공급처가 아니라 **배송비 묶음 단위**로 운영 중이다.

| 코드 | 이름 | 의미 |
|---|---|---|
| S00000HC | 일반합포2 | 박스내품 2 |
| S00000HD | 일반합포3 | 박스내품 3 |
| S00000HE | 일반합포4 | 박스내품 4 |
| S00000HJ | 일반합포5 | 박스내품 5 |
| S00000HK | 일반합포6 | 박스내품 6 |
| S00000HL | 일반합포8 | 박스내품 8 |
| **S00000HM** | **무료배송** | 배송비 수취 0 |

→ **`unit_list.박스내품` 하나로 자동 배정 가능.** 합포7은 해당 규격이 없어 미개설.
그 외 `S00000GP~HB`는 규격별 합포 그룹(240~250ml 30개*2, 340~350 페트 2합포 등), `S0000000`은 기본.

**검증법**: 등재분의 `공급사` ↔ `unit_list.박스내품` 대조. 2026-08-20 기준 선물세트 36건 중 35건 일치,
불일치 1건은 `45-20-+01`(박스내품5인데 합포6 — 배송비 누수, 사용자 확인 대기).

## 3. 무료배송 리스팅

**개별발송 유도용**으로 1세트 리스팅마다 무료배송 짝을 만든다. 세 가지가 세트로 움직인다.

1. **공급사** = `S00000HM`
2. **판매가** = 일반 1세트가 **+ 3,000원**
3. **상품명** = `… 1세트 무료배송`

**+3,000이 정확히 떨어지는 이유**: 자사몰은 PG 3.3%가 판매가·배송비에 똑같이 붙으므로
배송비 수입 3,000을 판매가로 옮겨도 정산액이 동일. 역산하면 `2,901 ÷ 0.967 = 3,000`.
→ **마진율 불변.**

박스 리스팅도 같은 규칙: `P0000BCI` G호 3세트 무료배송 89,400 = 1세트 28,800 × 3 + 3,000.

⚠️ **상품명으로 판정하지 말 것.** 이름에 `무료배송`이 없는데 HM인 건(`P0000BCK`)과
이름에 있는데 HM이 아닌 건(`P00000QM` 17차)이 실제로 공존한다. **공급사가 정답.**

## 4. 이미지

- **상세설명(B1)** = CSV에 HTML `<img>`로 넣는다. **URL만 넣으면 텍스트로 박힌다**(에디터 문자수가 URL 길이와 같으면 그 증상).
  B1 원본 폭 860px, 높이는 제각각 → `max-width:100%;height:auto`로 감쌀 것.
- **대표이미지(A1)** = **CSV로 못 넣는다.** 등재분의 `이미지등록` 4칸은 전부 카페24 내부 경로
  (`202509/{md5}.jpg`)로, 카페24가 업로드받아 해시 리네임한 형태. 외부 URL을 적어도 안 먹는다.
  → **등록 후 관리자에서 수동 등록.** A1(1000×1000) zip으로 묶어 전달하는 게 표준.
- 소스 = `gi.esmplus.com/td680708/{관리코드}/{관리코드}_A1|B1.jpg` (jpg→png 폴백).
  대표 하나 올리면 목록·작은목록·축소는 카페24가 자동 리사이즈.

## 5. ★★ 다운로드 = 진열상태 필터가 기본으로 걸린다 (최대 함정)

카페24 상품목록 CSV 다운로드는 **검색조건이 그대로 반영된다.** 실측:

| 파일 | 행수 | 실제 필터 |
|---|---|---|
| `_53_` | 700 | 진열상태 Y만 |
| `_54_` | **723** | 전체 (진열 N 23건 포함) |
| `_56_` / `_57_` | 509 / 497 | 판매상태 Y만 |

→ **행수가 카탈로그 총수와 다르면 필터가 걸린 것.** 진열 Y가 100%인 export는 필터 증거.
전수 판정(등록 여부·상태)에는 **반드시 전체 export**를 받을 것.

실사고(2026-08-20): 700건 export를 전체로 착각해 **이미 등록된 5건을 "미등록"으로 판정**,
신규 등록 CSV에 넣어 사용자에게 전달했다. 앞서 "listing 스냅샷에 있는데 이 export엔 없는 게 7건"을
직접 계산해놓고도 "삭제됐나 보다"로 흘려보낸 게 결정적. **사용자가 "723건 아니었어?"라고 짚어줘서 발각.**
→ 파일을 받으면 **먼저 총 건수를 사용자에게 확인**한다.

## 6. 워크플로우 (신규 등록 표준 흐름)

1. **전체 export 확보** (진열·판매 필터 전부 해제) → 총 건수 사용자 확인
2. **등재갭 산출** — 대상 관리코드 ↔ export `모델명`(대괄호 제거) 대조. `상품분류 번호`만 보면
   다른 분류로 등록된 건을 놓친다(예: 정관장 55-08이 `61|150`에 있었음) → **전 컬럼 풀텍스트 검색**으로 교차확인
3. **분기** — 등록됨+진열/판매 Y = 손댈 것 없음 / 등록됨+N = **재개**(상태 토글, CSV 불요) / 없음 = **신규 등록**
4. **가격 산정** — `compute_listing` 정산식 역산(§7)
5. **CSV 생성** — 90열 양식, 신규는 상품코드 공란
6. 사용자 업로드 → **A1 이미지 수동 등록**
7. **재다운로드 → `hapo_multiplier.csv`에 N 등록** (§8)
8. **재고 0 판매중지**

## 7. 가격 산정 (자사몰 정산식)

```
수수료(PG) 3.3% · 배송비 수입 3,000 · 실택배비 2,700
정산액 = 판매가 × 0.967 + 3,000 × 0.967      (무료배송은 뒤 항 없음)
마진율 = (정산액 − 매입가 − 2,700) / 정산액
권장가 = ceil100( ((매입가 + 2700)/(1−m) − 3000×0.967) / 0.967 )
```
1세트 매입가 = `박스매입단가 ÷ 박스내품` = `product_master.매입단가`.

**매입단가 충돌 시**: 시즌 특별단가 전표와 `product_master`가 다르면 사용자 지시에 따름
(2026-08-20은 **비싼 쪽 채택** — 보수적).

## 8. hapo N 등록 (필수 후속)

자사몰은 `n_source:"ref"` → `hapo_multiplier.csv` 사용. 키 = **상품코드**(`P0000…`), 채널 컬럼은 공란.
- 1세트 리스팅 → `N = 1 ÷ 박스내품` (0.3333…/0.25/0.2/0.1666…)
- 박스 리스팅에서 세트수 = 박스내품이면 `N=1` → **등록 생략**
- 미등록 시 박스매입가가 통째로 잡혀 **마진 −113~−420%**

⚠️ **판매Y만 담긴 export로 작업하면 판매중지분이 누락된다.** 여러 export를 합쳐 유니크 상품코드로 등록할 것.

## 9. 전용 함정

- **`45-20-+01`은 오타가 아니다.** ERP 관리코드 자체가 그렇다(`unit_list` 77행 `애경사랑다온14호(5세트)(32)`).
  자사몰 등재명은 「애경사랑 13호」로 달라 이름만 보면 다른 상품처럼 보인다.
- **더미가 999,999** — 등록만 해두고 못 사게 막는 장치(`55-08` 정관장·`24-15-03` 맥심 등).
  업로드 양식의 공급가 500000과는 다른 용도.
- **같은 관리코드 복수 리스팅이 정상** — 1세트/무료배송/박스가 각각 별도 상품코드.
  재고는 공유하므로 세트환산 재고를 합산하면 안 된다(`45-07` G호 1세트+3세트 = 재고 1,186 공유).
- **품절 처리는 진열 Y 유지 · 판매만 N** — 진열까지 끄면 검색·카테고리에서 사라져 재입고 시 노출이 처음부터 쌓인다.
  실제 자사몰 243건이 이 형태.
- 상품코드는 `P` + base36 연번. 업로드 순서대로 연속 발급되므로 **업로드 시트 행 순서와 1:1 대응**한다
  (과거 업로드본과 등재분을 맞춰볼 때 유용한 지문).

## 12. ★ CSV 수정 모드 (2026-09-02 검증 완료)

**결론 두 가지 — 실측으로 확정.**

1. ✅ **수정 모드는 동작한다.** `상품코드`(`P0000…`) 기입 → 해당 상품이 갱신된다.
   2026-09-02 `P0000BCK`로 상세설명 교체 성공(`<img>` 1개·생 URL 0), 판매가 등 값 있는 필드 전부 보존.
2. ❌ **공란 = 삭제다.** 값을 채운 38개 컬럼은 모두 보존됐는데
   **의도적으로 비운 `이미지등록` 4칸만 삭제되어 A1 대표이미지가 사라졌다.**

### 그래서 수정 CSV는 이렇게 만든다
- **다운로드본의 현재값을 90열에 전량 복사**한 뒤, 바꿀 칸만 덮어쓴다. 비우지 않는다.
- **`이미지등록(상세/목록/작은목록/축소)` 4칸도 반드시 되채운다.** 값은 카페24 내부 해시 경로
  (`202509/<md5>.jpg`)이며 **되써넣어도 정상 동작한다**. "내부 경로라 거부될 것"이라는 추측으로
  비웠다가 사고가 났다 — **비우는 쪽이 훨씬 위험하다.**
- 검증: 바꿀 칸 외 **89개 컬럼 diff 0**을 커밋 전에 확인.
- 복구 가능성: 삭제된 이미지도 **파일 자체는 서버에 남는다**

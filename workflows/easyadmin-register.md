# easyadmin-register (이지어드민 상품등록) — 플랫폼 인스턴스

> 공통 개념(낱개/박스 · 정제상품명 · 서식 일치)은 **workflows/product-registration-common.md** 참조.
> 이 문서는 **이지어드민 전용**. 신규 상품은 모든 판매채널 외에 이지어드민에도 등록해야 함.

## 채널 성격
- **판매 플랫폼이 아님 — 정산 관련 채널(ERP/정산).** 모든 신규 상품이 거쳐가야 하는 필수 경유 채널.
- 그래서 스마트스토어와 달리 **판매가 공식·카테고리·이미지·수수료 무관**. 명칭·공급처·합포 정보만 입력.

## 양식 / 기입 대상
- 업로드 파일 = `상품등록(실제 업로드파일)` 시트. **69열**. 2행에 `기입` 표시된 **7개 열만** 채움, 나머지 빈칸 유지. 서식 100% 보존(openpyxl read_only 금지).
- 시트 구성: `상품등록(실제 업로드파일)`(양식, 1행 헤더/2행 기입표시) · `예시참고`(등록 후 **export 포맷** — 열 배치 다름, 헤더명으로 매핑) · `넣어야할것`(이번 신규 = 스마트스토어 등록 품목 = 판매자상품코드+정제상품명).
- 데이터행은 **2행부터** (기입표시행 덮어씀).

## 기입 7열 규칙 (낱개 vs 박스)
모드 판별: 판매자상품코드 `PC…` = **낱개** / 그 외(관리코드 `01-09-01` 등) = **박스**.

| 열 | 항목 | 낱개(PC) | 박스(관리코드) |
|---|---|---|---|
| A | 상품명 | `[PC코드][낱개1개][{이름}ㅁ1개입ㅁ]` (레거시) | `[관리코드]{정제상품명}` |
| B | 공급처코드/공급처명 | `20010` (일괄 고정) | `20010` |
| C | 공급처 상품명 | A에서 맨앞 `[PC코드]` 제거 | A에서 맨앞 `[관리코드]` 제거(=정제명) |
| D | 공급처 옵션 | = A (그대로) | `[관리코드]-{정제풀네임} [{용량}*{박스내품}]` |
| E | 원산지 | = C | = C |
| AB | 합포불가 | `4` (고정) | `4` |
| AC | 동일상품 합포가능 수량 | `박스내품` | `합포장`(기본 1) |

### 핵심 포인트
- **낱개 A 레거시 형식**: `{이름}` = 정제상품명에서 끝 ` 1개` 제거. 구분자 `ㅁ` = 한글 자음 **ㅁ (U+3141)** 그대로 박음. `[낱개1개]`·`1개입` 의 1은 낱개 고정(항상 1).
- **박스 D 공급처 옵션**: 풀네임 전체가 들어감(브랜드 분리·축약 안 함). `[규격]` = product_master 규격을 `[용량*박스내품]` 대괄호로(예 `(20g*45)`→`[20g*45]`, `800g*10`→`[800g*10]`). 낱개 D는 A와 동일.
- **AC = "한 번 배송에 묶이는 동일상품 수량"**: 낱개=박스내품(1박스분), 박스=합포장(묶음 박스 수, 기본 1). 사용자가 따로 말 없으면 이 기본값이 정답. 가벼워 여러 박스 묶는 품목만 합포장 별도 지정.
- B=20010(공급처 "기타" 코드)·AB=4 는 전 품목 고정.

## ★ 선물세트 전용 규칙 (2026-08-13 확립 — 기존 61건 실물 대조)

일반 낱개/박스 규칙과 **다르다**. 근거 = 이지어드민 `전체상품목록` export(선물세트 61건) 전수 확인.

### (1) 코드당 **1건만** 등록 — 그 1건이 "1세트"
채널(ESM 등)엔 1세트·박스 2건을 올리지만 **이지어드민은 1건**. 박스 주문은 수량으로 잡히며,
`AC 동일상품 합포가능 수량 = 박스내품`이 그 역할을 한다. (PC코드 없음 — 선물세트는 자기참조, giftset-season-ops §8-B)

### (2) 기입 7열 (선물세트)
| 열 | 값 | 예 (45-07-06) |
|---|---|---|
| A 상품명 | `[관리코드]{이름}(BOX/{박스내품}) 1세트` | `[45-07-06]CJ 스팸 복합스페셜 J호(BOX/3) 1세트` |
| B 공급처 | **20035**(백설) — 아래 주의 | `20035` |
| C 공급처 상품명 | A에서 맨앞 `[관리코드]` 제거 | `CJ 스팸 복합스페셜 J호(BOX/3) 1세트` |
| D 공급처 옵션 | **= A 그대로**(박스 규칙 아님) | `[45-07-06]CJ 스팸…(BOX/3) 1세트` |
| E 원산지 | = C | 〃 |
| AB 합포불가 | **4** | 4 |
| AC 동일상품 합포가능 수량 | **박스내품** | 3 |

- ★ **D는 낱개 규칙(D=A)을 따른다.** 문서 상단의 박스 규칙(`[관리코드]-{풀네임} [{용량}*{박스내품}]`)이 아니다.
  선물세트는 형식상 "1세트" 단위라 낱개 취급. 최근 8건 전부 D=A.
- ★ **B 공급처코드는 20010 고정이 아니다.** 선물세트 61건이 9개 공급처에 흩어져 있음
  (선물셋트 20003×27 · 동원에프앤비 20026×9 · 백설 20035×8 · 제일제당-씨제이 20012×7 · 기타 20010×5 …).
  **CJ 계열 최근 등록분은 20035(백설)** — 02009 스팸12K호·02010 H-2호·01410 N호(같은 45-07 계열).
  구 등록분(2023년 G호 00031)은 20003 선물셋트. **브랜드/시기별로 다르므로 같은 계열 최근 건을 보고 맞출 것.**
- ★ **AB 합포불가는 시기별 2갈래**: 구 등록분(상품코드 ~012xx)=`1`, 최근(013xx~)=`4`. **현행 = 4**.
- 표기 형식도 변천: `1세트/(3/BOX)`(구) → **`(BOX/3) 1세트`(현행, 02008~02028)**.

### (3) ★ erp관리코드는 **업로드 양식에 없다 — 등록 후 수동 기입**
`전체상품목록` export엔 `erp관리코드` 열이 있으나 **일괄등록 양식 69열에는 없다**.
→ **업로드 후 사용자가 수동으로 채운다**(2026-08-13 사용자 확인).
⚠️ 수동 입력이므로 오배정이 발생한다 — 리치스파인애플슬라이스(02169) erp관리코드 오배정 사고와 동일 경로.
**등록 직후 4건 대조 검증을 절차에 포함할 것.**

### (4) 자동 생성 열 (기입 불필요)
바코드 `TD1{상품코드}` · 판매상태 `1` · 재고관리 `사용` · 대표상품 `0` · 공급가/판매가 `0`.

### (5) 양식 실물 (v10)
★ **자산 위치(2026-08-31 박제)**: `work-automation-app` → `reference/easyadmin_bulk_template.xls`
(= `상품_일괄등록_샘플_v10.xls` 원본 바이트 그대로, 26,624 bytes, md5 `a0c583646ab32c696605770b8e10ad74`).
**더 이상 사용자에게 재요청하지 말 것.** raw 다운로드해서 바로 클론.

`상품_일괄등록_샘플_v10.xls` = **OLE2 .xls · 시트 `Sheet1` 1개 · 69열 · 헤더 1행뿐**.

★ 기입 7열 인덱스(0-based)는 **헤더명으로 찾을 것**(하드코딩 금지):
`상품명`0 · `공급처코드 / 공급처명`1 · `공급처 상품명`2 · `공급처 옵션`3 · `원산지`4 ·
`합포불가`**27**(AB) · `동일상품 합포가능 수량`**28**(AC).
→ ⚠️ 문서 상단의 "2행에 기입 표시, 데이터 2행부터"는 **이 v10에 해당 없음**(기입표시 행 없음). 데이터는 **2행부터**가 맞다.
★ 산출은 **xlutils.copy로 원본 .xls 클론 후 기입**(새 .xlsx 재생성 아님) — 형식 100% 보존.
  `xlrd.open_workbook(src, formatting_info=True)` → `xlutils.copy` → `ws.write(r,c,v)` → `.xls` 저장.

### (6) 처리 배치
- **선물세트 신규 4종(2026-08-13)** — 45-07-06 J호(AC=3)·45-07-05 I호(AC=4)·45-07-08 L-3호(AC=5)·45-07-09 L-2호(AC=3).

## 생성 절차
1. 양식 원본 load_workbook(read_only 금지) → 3시트·69열·서식 보존.
2. `상품등록` 시트 2행부터 7열만 기입(값만 set, number_format 건드리지 않음).
3. 재로드 검증: 헤더/열수(69)/행수/샘플 행 타입 확인.
